Ζητάτε από έναν πράκτορα να βρει τα ανοιχτά bugs του έργου σας και να ετοιμάσει ένα προσχέδιο για θέμα παρακολούθησης. Για να το κάνει, δεν αρκούν οι καλές οδηγίες. Χρειάζεται τρόπο να φτάσει στο σύστημα παρακολούθησης θεμάτων, να διαβάσει τα σωστά δεδομένα και πιθανώς να δημιουργήσει κάτι εκεί.

Εδώ χρειάζονται τα **εργαλεία**, οι **συνδέσεις υπηρεσιών (connectors)** και το **MCP**. Σχετίζονται, αλλά περιγράφουν διαφορετικά μέρη της εγκατάστασης.

## Τι περιέχει ένα εργαλείο

Ένα εργαλείο συνήθως έχει **όνομα**, **περιγραφή**, **σχήμα εισόδου** και μια υλοποίηση που κάνει τη δουλειά. Η περιγραφή βοηθά το μοντέλο να αποφασίσει πότε θα το χρησιμοποιήσει. Το σχήμα περιγράφει τα ορίσματα που δέχεται.

Ακολουθεί ένας μικρός ορισμός φανταστικού εργαλείου MCP:

<Collapsible title="Δείτε τον ορισμό του search_issues">

```json
{
  "name": "search_issues",
  "description": "Αναζήτηση θεμάτων στο συνδεδεμένο έργο. Αυτό το εργαλείο μόνο διαβάζει δεδομένα.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": { "type": "string" },
      "limit": { "type": "integer", "minimum": 1, "maximum": 20 }
    },
    "required": ["query"],
    "additionalProperties": false
  }
}
```

</Collapsible>

Το μοντέλο μπορεί να ζητήσει το `search_issues` με `{"query": "ανοιχτά bugs", "limit": 3}`. Η εφαρμογή που το περιβάλλει στέλνει το αίτημα στην υλοποίηση. Η υλοποίηση ρωτά το σύστημα θεμάτων και επιστρέφει αποτελέσματα ή σφάλμα.

Το όνομα και το σχήμα δεν εκτελούν τίποτα από μόνα τους. Η υλοποίηση πρέπει να επικυρώσει τις εισόδους, να ελέγξει την πρόσβαση και να εκτελέσει την πραγματική λειτουργία. Η απάντηση του εργαλείου είναι επίσης ξεχωριστή από την τελική απάντηση του μοντέλου: μπορεί να περιέχει ID και τίτλους θεμάτων, τα οποία μετά συνοψίζει το μοντέλο. Η [προδιαγραφή εργαλείων MCP](https://modelcontextprotocol.io/specification/latest/server/tools) περιγράφει πώς τα εργαλεία παρέχουν αυτές τις λειτουργίες.

<Callout type="info" title="Το αίτημα δεν είναι αποτέλεσμα">
Το «Θα δημιουργήσω ένα θέμα» είναι δήλωση. Η κλήση εργαλείου ζητά την εκτέλεση της λειτουργίας. Μια επιτυχής απάντηση με το ID του νέου θέματος είναι στοιχείο ότι η λειτουργία έγινε. Κρατήστε αυτά τα τρία πράγματα ξεχωριστά.
</Callout>

### Ένα εργαλείο μπορεί να αντιπροσωπεύει μια ολόκληρη ροή εργασίας

Μέχρι τώρα κάθε εργαλείο ήταν μία λειτουργία: αναζήτηση, δημιουργία, εξαγωγή. Όμως πίσω από το όνομα ενός εργαλείου μπορεί να κρύβεται κάτι πολύ μεγαλύτερο: μια ολόκληρη διαδικασία, γραμμένη από πριν και εκτελούμενη από μια μηχανή ροών εργασίας (workflow engine). Ο πράκτορας εξακολουθεί να αποφασίζει **πότε** θα την ξεκινήσει και **ποια δεδομένα** θα της δώσει. Όλα τα υπόλοιπα γίνονται ακριβώς όπως ορίζει η διαδικασία, με την ίδια σειρά, κάθε φορά.

Σκεφτείτε μια επιστροφή χρημάτων. Ένας πράκτορας υποστήριξης μπορεί να καταλαβαίνει πολύ καλά έναν εκνευρισμένο πελάτη, αλλά μάλλον δεν θέλετε να αυτοσχεδιάζει με την πολιτική επιστροφών σας. Πακεταρισμένη ως ένα μόνο εργαλείο, η ροή επιστροφής ελέγχει πρώτα αν ο πελάτης δικαιούται επιστροφή, ζητά έπειτα έγκριση από έναν υπεύθυνο και στο τέλος πιστώνει το ποσό, όποια κι αν είναι η συζήτηση που την ξεκίνησε. Οι εγκρίσεις, οι αναπτύξεις (deployments) και άλλες διαδικασίες όπου τα βήματα *είναι* η πολιτική ταιριάζουν στο ίδιο καλούπι. Οι μηχανές ροών εργασίας συνήθως κρατούν αρχείο για κάθε εκτέλεση, οπότε ο πράκτορας μπορεί επίσης να ανατρέξει σε παλαιότερες εκτελέσεις και να σας πει ποιες απέτυχαν μέσα στη νύχτα και σε ποιο βήμα, αντί να μαντεύει.

Ένα πρόσφατο παράδειγμα έρχεται από την AWS. Στις 29 Οκτωβρίου 2026 [ανακοίνωσε](https://aws.amazon.com/about-aws/whats-new/2026/10/step-functions-workflows-ai-agent-tools/) ότι οι ροές εργασίας του Step Functions μπορούν να χρησιμοποιηθούν ως εργαλεία πρακτόρων μέσω του Amazon Bedrock AgentCore Gateway, που συνδέει πράκτορες με εργαλεία μέσω MCP. Η ιδέα όμως δεν ανήκει σε έναν πάροχο: ένα pipeline CI, μια ροή έγκρισης σε σύστημα αιτημάτων ή ένα script που η ομάδα σας ήδη εμπιστεύεται μπορούν να προσφερθούν σε έναν πράκτορα με τον ίδιο τρόπο.

Πρόκειται για μοιρασιά δύο δυνατών σημείων. Το μοντέλο είναι ευέλικτο: μπορεί να διαβάσει μια ασυνήθιστη κατάσταση και να επιλέξει ένα λογικό επόμενο βήμα. Η ροή εργασίας είναι προβλέψιμη: τα ίδια δεδομένα περνούν από τα ίδια βήματα. Αν αφήσετε τη στιγμή στον πράκτορα και τα βήματα στη ροή, κάθε δύναμη μπαίνει εκεί που ταιριάζει. Αυτό αλλάζει και την προτροπή. Περιγράψτε τον στόχο και πότε πρέπει να κληθεί η ροή, όχι τα βήματα που περιέχει. Αν επαναλάβετε τα βήματα, δημιουργείτε ένα δεύτερο αντίγραφο της πολιτικής, που μπορεί να απομακρυνθεί από το πραγματικό και που το μοντέλο ίσως προσπαθήσει να ακολουθήσει μόνο του, με το χέρι.

### Ένα εργαλείο μπορεί να είναι και ένας άλλος πράκτορας

Πίσω από το όνομα ενός μόνο εργαλείου μπορεί να κρύβεται και μια δεύτερη μορφή. Αντί για μια σταθερή διαδικασία, η υλοποίηση μπορεί να είναι από μόνη της ένας πράκτορας. Δέχεται ένα αίτημα και τρέχει τον δικό του βρόχο: σχεδιάζει, ψάχνει, ζυγίζει ό,τι βρίσκει, ίσως γράφει και εκτελεί κώδικα στην πορεία, και παραδίδει ένα ολοκληρωμένο αποτέλεσμα, όπως μια απάντηση με παραπομπές, μια αναφορά ή ένα αρχείο. Για τον πράκτορα που τον κάλεσε, όλα αυτά μοιάζουν με μία κλήση εργαλείου και μία απάντηση.

Αυτό αλλάζει τι πρέπει να κάνει ο πράκτορας που καλεί. Με λεπτά εργαλεία ανάκτησης, ο εξωτερικός πράκτορας κάνει μόνος του την έρευνα. Αποφασίζει ποια πηγή θα ρωτήσει, διαβάζει ό,τι επιστρέφει, προσέχει μια αντίφαση και ψάχνει ξανά. Κάθε βήμα γίνεται μέσα στο δικό του παράθυρο συμφραζομένων, και κάθε ακατέργαστο αποτέλεσμα που διαβάζει μένει εκεί ως το τέλος της εργασίας. Ένας εξειδικευμένος πράκτορας δέχεται έναν **στόχο** αντί για μια σειρά από κλήσεις εργαλείων. Τα λεπτομερή βήματα γίνονται στα συμφραζόμενα του ειδικού και όχι στα δικά σας, οπότε τα συμφραζόμενα του εξωτερικού πράκτορα μένουν πιο σύντομα και η προσοχή του μένει στη μεγαλύτερη εργασία: τι ζητήσατε, τι ξέρει ήδη και τι πρέπει να γίνει με το αποτέλεσμα.

Δύο πρόσφατα παραδείγματα δείχνουν την ιδέα από διαφορετικές πλευρές. Στις 4 Νοεμβρίου 2026, η AlphaSense [παρουσίασε](https://www.alpha-sense.com/resources/product-articles/superanalyst-mcp/) το SuperAnalyst MCP, το οποίο περιγράφει ως πράκτορα στον οποίο αναθέτετε σύνθετη οικονομική και επιχειρηματική έρευνα. Σχεδιάζει την έρευνα, συγκεντρώνει πηγές από τη βιβλιοθήκη εγγράφων της εταιρείας, εκτελεί την ανάλυση και επιστρέφει συμφραζόμενα με παραπομπές που δείχνουν πίσω στα αρχικά αποσπάσματα, στη μορφή που ζητά το αίτημα: μια άμεση απάντηση, ένα υπολογιστικό φύλλο ή έναν φάκελο τεκμηρίων με πηγές. Στον ανοιχτό κώδικα, ο [διακομιστής MCP του GPT Researcher](https://github.com/assafelovic/gptr-mcp) κάνει κάτι παρόμοιο για τον ανοιχτό ιστό. Το εργαλείο του `deep_research` δέχεται ένα μόνο ερώτημα και εκτελεί έναν ολόκληρο γύρο έρευνας που εξερευνά και επαληθεύει αρκετές πηγές. Σύμφωνα με την [τεκμηρίωσή](https://docs.gptr.dev/docs/gpt-researcher/mcp-server/getting-started) του, αυτό διαρκεί περίπου 30 με 40 δευτερόλεπτα αντί για τη σχεδόν άμεση απάντηση μιας απλής αναζήτησης. Επιστρέφει τα συμφραζόμενα και τις πηγές που συγκέντρωσε μαζί με ένα αναγνωριστικό έρευνας, πάνω στο οποίο μπορούν να χτίσουν συνοδευτικά εργαλεία όπως τα `write_report` και `get_research_sources`. Ο ίδιος διακομιστής προσφέρει επίσης το `quick_search` για όταν αρκεί μια γρήγορη, επιφανειακή ματιά, μια χρήσιμη υπενθύμιση ότι οι δύο μορφές μπορούν να συνυπάρχουν.

Βάλτε το αυτό δίπλα στη ροή εργασίας της προηγούμενης ενότητας. Μια ροή εργασίας είναι προβλέψιμη: τα ίδια δεδομένα περνούν κάθε φορά από τα ίδια βήματα, και εκεί βρίσκεται η αξία της. Ένας εμφωλευμένος πράκτορας είναι ευέλικτος: επιλέγει μόνος του το επόμενο βήμα, και εκεί βρίσκεται κι η δική του αξία. Όμως η ευελιξία φέρνει τα ίδια ερωτήματα που θα θέτατε σε κάθε πράκτορα στον οποίο εμπιστεύεστε εργαλεία. Βλέπετε λιγότερα από κάθε βήμα, συχνά μόνο το αποτέλεσμα και όποιο ίχνος επιλέξει να επιστρέψει. Εμπιστεύεστε τις πηγές του, την κρίση του για το ποιες μετράνε και τη δική του προσοχή απέναντι σε παραπλανητικό περιεχόμενο. Και μια μακριά εμφωλευμένη εκτέλεση εξακολουθεί να κοστίζει tokens και χρόνο, ακόμη κι όταν αυτά ξοδεύονται μακριά από τα μάτια σας. Αποφασίστε λοιπόν ρωτώντας σε ποιον ανήκει η κρίση. Όταν το ζύγισμα των πηγών και η επιλογή του τι θα κοιτάξει κανείς μετά *είναι* η ίδια η εξειδίκευση, αφήστε το στον ειδικό. Όταν τα βήματα *είναι* η ίδια η πολιτική, μείνετε σε μια σταθερή ροή εργασίας.

Από εκεί προκύπτει και το prompt. Περιγράψτε τον στόχο και τη μορφή που πρέπει να έχει η απάντηση, και ζητήστε πηγές ή μια σημείωση για την αβεβαιότητα όταν αυτά μετράνε. Μην απαριθμείτε τα εσωτερικά βήματα του ειδικού. Έχει ήδη τα δικά του, και ένα δεύτερο αντίγραφο γραμμένο στο prompt σας απλώς θα τα ανταγωνίζεται.

### Όταν δεν υπάρχει API, η οθόνη γίνεται εργαλείο

Κάθε εργαλείο που είδαμε ως τώρα είχε μια πόρτα φτιαγμένη για λογισμικό: ένα API, έναν connector, έναν διακομιστή MCP. Πολλά συστήματα δεν έχουν τέτοια πόρτα. Μια παλιά εσωτερική πύλη, ο ιστότοπος κρατήσεων ενός προμηθευτή, ένα πρόγραμμα υπολογιστή από άλλη δεκαετία: οι άνθρωποι τα χρησιμοποιούν κάθε μέρα, αλλά μόνο μέσα από την οθόνη. Για τέτοια συστήματα, ορισμένα μοντέλα μπορούν να αντιμετωπίσουν την ίδια την οθόνη ως εργαλείο. Αυτό συνήθως λέγεται **computer use**, δηλαδή χρήση υπολογιστή.

Ο μηχανισμός είναι ο βρόχος που ήδη γνωρίζετε, με εικόνες στη θέση των δεδομένων. Η εφαρμογή που τρέχει το μοντέλο στέλνει την εργασία και ένα στιγμιότυπο οθόνης. Το μοντέλο το κοιτάζει και απαντά όχι με πεζό κείμενο αλλά με μια δομημένη ενέργεια: κάνε κλικ σε αυτό το σημείο, πληκτρολόγησε αυτό το κείμενο, κύλησε προς τα κάτω. Μερικά εργαλεία επισυνάπτουν επίσης σε κάθε ενέργεια μια σύντομη δήλωση πρόθεσης, όπως «Κάνε κλικ στο πλαίσιο αναζήτησης για να πληκτρολογήσεις τον προορισμό», κι έτσι μια εκτέλεση παρακολουθείται πιο εύκολα. Το μοντέλο εξακολουθεί να μη μετακινεί τίποτα μόνο του. Ο κώδικας του ίδιου του προγραμματιστή εκτελεί την ενέργεια, παίρνει νέο στιγμιότυπο και το στέλνει πίσω. Κοιτάς, ενεργείς, ξανακοιτάς, ώσπου να τελειώσει η εργασία ή να σταματήσει κάποιος τον βρόχο. Το πού τρέχει αυτός ο βρόχος μετράει όσο και το πώς λειτουργεί, και σε αυτό ακριβώς το ερώτημα στέκεται η ενότητα [Ο υπολογιστής του bot](/book/28-persistent-bots) στο κεφάλαιο «Πάντα Ενεργά Bots».

Στις 30 Οκτωβρίου 2026 η Google έκανε το εργαλείο της Computer Use γενικά διαθέσιμο στο Gemini API ([σημειώσεις έκδοσης](https://ai.google.dev/gemini-api/docs/changelog)). Η [τεκμηρίωσή του](https://ai.google.dev/gemini-api/docs/computer-use) περιγράφει περιβάλλοντα προγράμματος περιήγησης, κινητών συσκευών και υπολογιστών, ενέργειες που φέρουν πεδίο `intent`, ρυθμιζόμενες πολιτικές ασφάλειας που μπορούν να μπλοκάρουν μια ενέργεια ή να ζητήσουν επιβεβαίωση πριν από βήματα όπως μια πληρωμή, και προαιρετικό έλεγχο των στιγμιότυπων για κρυμμένη έγχυση προτροπών. Η ίδια η Google συνιστά στενή επίβλεψη για τις σημαντικές εργασίες. Η ιδέα δεν ανήκει σε μία μόνο εταιρεία: η Anthropic προσφέρει ένα [εργαλείο computer use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool) για το Claude και η OpenAI ένα [εργαλείο computer](https://platform.openai.com/docs/guides/tools-computer-use) στο Responses API της, και τα δύο χτισμένα γύρω από την ίδια ανταλλαγή στιγμιότυπων και ενεργειών που εκτελεί η εφαρμογή σας.

Τα υπέρ και τα κατά αξίζουν απλά λόγια. Η ανάγνωση μιας οθόνης είναι πιο αργή από την κλήση ενός API, κάθε στιγμιότυπο κοστίζει tokens, και ένα κουμπί που άλλαξε θέση ή ένα απρόσμενο αναδυόμενο παράθυρο μπορεί να χαλάσει μια εκτέλεση που χθες δούλευε. Γι' αυτό, όταν υπάρχει πραγματικό API ή connector, προτιμήστε το, και κρατήστε το computer use για τα συστήματα που δεν αφήνουν άλλο δρόμο. Η οθόνη είναι επίσης μια είσοδος σαν όλες τις άλλες: το κείμενο μιας σελίδας μπορεί να κουβαλά έγχυση προτροπών όπως ακριβώς ένα έγγραφο, και το ότι το βλέπετε σε μια εικόνα δεν το κάνει πιο αξιόπιστο. Και επειδή το μοντέλο μπορεί να κάνει κλικ σε οτιδήποτε θα μπορούσε ένας άνθρωπος, τα ριψοκίνδυνα βήματα, όπως η πληρωμή, η διαγραφή ή η αλλαγή δεδομένων, πρέπει να περιμένουν να τα επιβεβαιώσει ένας άνθρωπος.

Ωστόσο, το στιγμιότυπο οθόνης δεν είναι ο μόνος τρόπος να δεις μια οθόνη. Τα λειτουργικά συστήματα και τα προγράμματα περιήγησης κρατούν ήδη μια δεύτερη, πιο αθόρυβη περιγραφή κάθε παραθύρου: το **δέντρο προσβασιμότητας**, το δομημένο περίγραμμα με τα κουμπιά, τα πεδία, τα μενού και τις ετικέτες που δημοσιεύουν ώστε οι αναγνώστες οθόνης να μπορούν να πουν σε όποιον δεν βλέπει την οθόνη τι υπάρχει εκεί και τι μπορεί να πατηθεί. Αυτό το περίγραμμα μπορεί να το διαβάσει και ένας πράκτορας. Αντί για εικόνα, το εργαλείο παίρνει ένα snapshot που απαριθμεί κάθε στοιχείο πάνω στο οποίο μπορεί να δράσει ο πράκτορας, το καθένα με τον ρόλο του, το όνομά του και ένα σύντομο αναγνωριστικό αναφοράς. Το μοντέλο δεν χρειάζεται πια να μαντέψει σε ποιες συντεταγμένες βρίσκεται το κουμπί Αποθήκευση· ζητά κλικ στο στοιχείο με εκείνη την αναφορά. Έπειτα παίρνει ένα καινούργιο snapshot και ξανακοιτάζει, γιατί ένα κλικ που πέρασε δεν αποδεικνύει ότι η οθόνη άλλαξε. Η Vercel Labs έδωσε ως ανοιχτό κώδικα ένα παράδειγμα για εφαρμογές επιφάνειας εργασίας, το [agent-desktop](https://github.com/vercel-labs/agent-desktop): ένα εργαλείο γραμμής εντολών και μια βιβλιοθήκη C με άδεια Apache-2.0, που διαβάζουν τις διεπαφές προσβασιμότητας του macOS (το AX API), των Windows (UI Automation) και του Linux (AT-SPI) και επιστρέφουν τα snapshot τους σε JSON. Η [τεκμηρίωσή του](https://agent-browser.dev/desktop) φροντίζει να ξεκαθαρίσει ότι πρόκειται για εργαλείο που καλούν οι πράκτορες, όχι για πράκτορα: δεν έχει μέσα του κανένα μοντέλο, και ο βρόχος της παρατήρησης, της δράσης και της επαλήθευσης μένει σε όποιον το καλεί. Στο πρόγραμμα περιήγησης, ο [διακομιστής Playwright MCP](https://github.com/microsoft/playwright-mcp) της Microsoft ακολουθεί την ίδια ιδέα: επιτρέπει σε ένα μοντέλο να δουλεύει με ιστοσελίδες μέσα από snapshot προσβασιμότητας αντί για στιγμιότυπα οθόνης.

Κάθε τρόπος να βλέπεις έχει τις αρετές του και τα τυφλά του σημεία. Μια λίστα με ονομασμένα στοιχεία κοστίζει συνήθως λιγότερα tokens από μια εικόνα, δεν τα χάνει όταν ένα κουμπί μετακινηθεί λίγα pixel, και ορισμένα εργαλεία μπορούν να δράσουν μέσα από αυτήν χωρίς να κουνήσουν το ποντίκι ή να κλέψουν την εστίαση από τον άνθρωπο που κάθεται στο πληκτρολόγιο. Όμως το δέντρο δείχνει μόνο όσα επιλέγει να δημοσιεύσει μια εφαρμογή. Ένα πρόγραμμα φτιαγμένο χωρίς πληροφορίες προσβασιμότητας, ή ένας καμβάς, ένα παιχνίδι, οτιδήποτε ζωγραφίζεται ως σκέτα pixel, μένει αόρατο σε αυτό, και εκεί το στιγμιότυπο οθόνης παραμένει ο δρόμος προς τα μέσα. Γι' αυτό πολλά εργαλεία συνδυάζουν τα δύο: διαβάζουν πρώτα το περίγραμμα και στρέφονται στην εικόνα όταν το περίγραμμα δεν φτάνει. Σημαίνει επίσης ότι η φροντίδα με την οποία μια ομάδα βάζει σωστές ετικέτες στην εφαρμογή της για όσους χρησιμοποιούν αναγνώστη οθόνης ανταμείβεται διπλά, γιατί αυτές ακριβώς τις ετικέτες διαβάζει και ένας πράκτορας.

Οι προτροπές ακολουθούν τους ίδιους κανόνες με πριν, μόνο που εδώ τα λάθη κοστίζουν περισσότερο, γιατί ένας ιστότοπος δεν μπορεί να πει στο μοντέλο τι εννοούσατε. Ονομάστε τον ακριβή ιστότοπο και τη σελίδα, πείτε πού τελειώνει η εργασία και τι πρέπει να επιβεβαιωθεί πριν γίνει οτιδήποτε.

## Τι προσθέτει ένας connector

Ένας connector συγκεντρώνει την ενσωμάτωση με ένα συγκεκριμένο σύστημα. Μπορεί να χειρίζεται τη σύνδεση χρήστη, την επιλογή λογαριασμού ή χώρου εργασίας, την εύρεση δεδομένων και την παροχή υποστηριζόμενων ενεργειών ως εργαλεία. Μερικοί connectors μόνο αναζητούν ή διαβάζουν. Άλλοι υποστηρίζουν και εγγραφές.

**Ο connector είναι όρος προϊόντος, όχι ένα ενιαίο τεχνικό πρότυπο.** Ένας connector μπορεί να καλεί απευθείας το API μιας υπηρεσίας. Άλλος μπορεί να χρησιμοποιεί διακομιστή MCP. Ένας τρίτος μπορεί να ψάχνει σε ευρετήριο από συγχρονισμένα έγγραφα. Ελέγξτε τι υποστηρίζει η συγκεκριμένη ενσωμάτωση. Η [επισκόπηση connectors](https://learn.microsoft.com/en-us/azure/connectors/introduction) της Microsoft δίνει ένα παράδειγμα ενσωματώσεων γύρω από API.

Η σύνδεση λογαριασμού δεν σημαίνει ότι ο πράκτορας βλέπει κάθε αρχείο, φορτώνει όλα τα δεδομένα σας στο πλαίσιό του ή έχει δικαίωμα για κάθε ενέργεια. Η πρόσβαση εξαρτάται από τον λογαριασμό, τα ρυθμισμένα πεδία δικαιωμάτων, την εφαρμογή και τα δικαιώματα της ίδιας της υπηρεσίας. Τα αποτελέσματα αναζήτησης μπορεί επίσης να προέρχονται από ευρετήριο παλαιότερο από τα αρχικά έγγραφα.

Για το σύστημα θεμάτων, ξεχωρίστε τα εξής: Έχει ρυθμιστεί σύνδεση; Σε ποιο έργο μπορεί να έχει πρόσβαση; Μπορεί μόνο να διαβάζει ή και να δημιουργεί θέματα;

## Τι τυποποιεί το MCP

Το **MCP** σημαίνει **Model Context Protocol**. Ορίζει έναν κοινό τρόπο επικοινωνίας ανάμεσα σε εφαρμογές AI και εξωτερικούς παρόχους δυνατοτήτων. Δεν αντικαθιστά το API μιας υπηρεσίας. Ένας διακομιστής MCP μπορεί να χρησιμοποιεί αυτό το API εσωτερικά.

Η [αρχιτεκτονική MCP](https://modelcontextprotocol.io/docs/learn/architecture) έχει τρεις βασικούς ρόλους:

Η συμβατότητα όμως παραμένει σημαντική: η κεντρική εφαρμογή και ο διακομιστής πρέπει να υποστηρίζουν τις δυνατότητες που θέλετε. Η εύρεση ενός εργαλείου δεν εγγυάται άδεια εκτέλεσης. ### Οι δεξιότητες μπορούν να έρχονται μαζί με τον διακομιστή

Μέχρι πρόσφατα, αυτά τα δύο κομμάτια έφταναν συνήθως χωριστά. Ένας διακομιστής μπορούσε να δώσει στον πράκτορα τα εργαλεία του, αλλά η τεχνογνωσία για να τα χρησιμοποιεί σωστά βρισκόταν αλλού: σε μια δεξιότητα που εγκαθίστατο ξεχωριστά, σε ένα README ή στην προτροπή του ίδιου του χρήστη. Όταν η υπηρεσία άλλαζε, αυτές οι οδηγίες μπορούσαν να μείνουν πίσω χωρίς να το καταλάβει κανείς.

Η επίσημη **επέκταση Skills** του MCP, που οριστικοποιήθηκε τον Σεπτέμβριο του 2026, κλείνει μεγάλο μέρος αυτού του κενού. Ένας διακομιστής μπορεί πλέον να προσφέρει όχι μόνο τα εργαλεία του αλλά και τις δεξιότητες που εξηγούν πώς να χρησιμοποιούνται, γραμμένες στην ίδια μορφή `SKILL.md` που περιγράφεται στο κεφάλαιο [Πράκτορες και Δεξιότητες](/book/25-agents-and-skills). Τα εργαλεία λένε στον πράκτορα τι μπορεί να κάνει. Οι δεξιότητες του λένε πώς να κάνει καλά τη δουλειά. Τώρα και τα δύο μπορούν να έρχονται από τον ίδιο διακομιστή, έτσι οι οδηγίες βρίσκονται δίπλα στην υπηρεσία που περιγράφουν και μπορούν να ενημερώνονται από όσους τη συντηρούν.

Ο μηχανισμός στηρίζεται σε στοιχεία που έχετε ήδη γνωρίσει. Κάθε αρχείο μιας δεξιότητας εκτίθεται ως πόρος MCP, συνήθως με URI της μορφής `skill://`. Ένας πελάτης μπορεί να απαριθμήσει τις δεξιότητες ενός διακομιστή με `skills/list`, να ανακτήσει μία με `skills/get` και να διαβάσει τα συνοδευτικά της αρχεία με `resources/read`.

Σε κάθε περίπτωση, οι πλήρεις οδηγίες μπαίνουν στο πλαίσιο μόνο όταν χρειάζονται, και η ανάγνωση ενός αρχείου `SKILL.md` δεν ενεργοποιεί από μόνη της τη δεξιότητα.

### Όταν ένα εργαλείο χρειάζεται χρόνο ή μια απάντηση

Οι περισσότερες κλήσεις εργαλείων είναι σύντομες ανταλλαγές: ο πράκτορας ζητά, ο διακομιστής απαντά και η δουλειά προχωρά. Κάποιες εργασίες όμως δεν ταιριάζουν σε αυτόν τον ρυθμό. Μια εις βάθος έρευνα, η εξαγωγή μιας μεγάλης αναφοράς ή ένα build μπορεί να κρατήσουν πολλά λεπτά, και κάποιες δουλειές φτάνουν σε ένα σημείο όπου μόνο ο χρήστης μπορεί να αποφασίσει τι θα γίνει μετά. Το MCP προσφέρει δύο ιδέες για τέτοιες στιγμές: τα **Tasks**, για δουλειά που χρειάζεται χρόνο, και το **elicitation** (αίτημα πληροφοριών από τον χρήστη), για δουλειά που χρειάζεται έναν άνθρωπο.

Η επίσημη [επέκταση Tasks](https://tasks.extensions.modelcontextprotocol.io/) (`io.modelcontextprotocol/tasks`) αλλάζει τον τρόπο που ολοκληρώνεται ένα αργό `tools/call`. Αντί να κρατά το αίτημα ανοιχτό μέχρι να τελειώσει η δουλειά, ο διακομιστής μπορεί να απαντήσει αμέσως με ένα μόνιμο αναγνωριστικό εργασίας (task handle), κάτι σαν το χαρτάκι που σας δίνουν στη γκαρνταρόμπα. Ο πελάτης μπορεί να ελέγξει την εργασία με `tasks/get`, να στείλει ενημερώσεις ή απαντήσεις με `tasks/update`, να τη σταματήσει με `tasks/cancel` και να πάρει το αποτέλεσμα όταν είναι έτοιμο. Στο μεταξύ, ο πράκτορας μπορεί να συνεχίσει να δουλεύει και να επιστρέψει αργότερα, κάτι που μετρά κυρίως για τα [πάντα ενεργά bots](/book/28-persistent-bots) που εκτελούν εργασίες όσο λείπετε. Τα Tasks είναι προαιρετικά και για τις δύο πλευρές: ο πελάτης δηλώνει υποστήριξη σε κάθε αίτημα και ο διακομιστής αποφασίζει, για κάθε αίτημα χωριστά, αν θα δημιουργήσει εργασία. Τα υπάρχοντα εργαλεία δεν αποκτούν αυτή τη δυνατότητα από μόνα τους· πρέπει να την προσθέσει ο δημιουργός του διακομιστή.

<Compare
  before={{ label: "Μια κλήση εργαλείου που μπλοκάρει", content: "Ο πράκτορας καλεί το export_report και περιμένει. Το αίτημα μένει ανοιχτό για λεπτά. Αν πέσει η σύνδεση, κανείς δεν ξέρει αν ολοκληρώθηκε η εξαγωγή, και μέχρι να έρθει απάντηση ο πράκτορας δεν μπορεί να κάνει τίποτε άλλο." }}
  after={{ label: "Ένα αναγνωριστικό εργασίας", content: "Ο πράκτορας καλεί το export_report και παίρνει αμέσως πίσω ένα αναγνωριστικό εργασίας. Περνά σε άλλη δουλειά, ελέγχει την εργασία με tasks/get και παίρνει την αναφορά μόλις είναι έτοιμη. Αν αλλάξουν τα σχέδια, το tasks/cancel τη σταματά." }}
/>

Το [elicitation](https://modelcontextprotocol.io/specification/latest/client/elicitation) επιτρέπει σε έναν διακομιστή να σταματήσει για λίγο και να ζητήσει από τον χρήστη δομημένα στοιχεία: «Να γίνει ανάπτυξη στο staging;», «Επιβεβαιώνετε αυτή την επιστροφή χρημάτων;» ή μια λεπτομέρεια που λείπει και χωρίς την οποία η δουλειά δεν μπορεί να συνεχιστεί. Η κεντρική εφαρμογή εμφανίζει μια μικρή φόρμα και ο χρήστης μπορεί να απαντήσει, να αρνηθεί ή να ακυρώσει. Η άρνηση είναι κι αυτή έγκυρη απάντηση, και ο διακομιστής αποφασίζει τι θα κάνει μετά. Οι δύο ιδέες συναντιούνται φυσικά: μια εργασία σε εξέλιξη μπορεί να σταματήσει στην κατάσταση `input_required` και να ρωτήσει κάτι τον χρήστη στη μέση της δουλειάς. Πριν από μια εγγραφή, μια τέτοια ερώτηση είναι ένα φυσικό σημείο ελέγχου όπου αποφασίζει ο άνθρωπος, ακριβώς εκεί όπου μετρά η απόφαση.

<Callout type="warning" title="Μια φόρμα από διακομιστή παραμένει αίτημα διακομιστή">
Ένα αίτημα elicitation έρχεται από τον διακομιστή, όχι από την εφαρμογή σας, γι' αυτό αξίζει τον ίδιο έλεγχο με κάθε έξοδο εργαλείου. Διαβάστε τι σας ζητά πριν απαντήσετε και μην πληκτρολογείτε ποτέ κωδικό πρόσβασης, κλειδί API ή άλλο μυστικό σε μια τέτοια φόρμα, εκτός αν εμπιστεύεστε τον διακομιστή. Η υποστήριξη διαφέρει επίσης από εφαρμογή σε εφαρμογή: το VS Code [τεκμηριώνει υποστήριξη για elicitation](https://code.visualstudio.com/api/extension-guides/ai/mcp), το Cursor υποστηρίζει elicitation και το Claude Code πρόσθεσε [MCP Tasks και elicitation](https://code.claude.com/docs/en/mcp) σε δημόσια beta στην εφαρμογή τερματικού του, όχι όμως ακόμη παντού όπου λειτουργεί. Ο επίσημος [πίνακας υποστήριξης πελατών](https://modelcontextprotocol.io/extensions/client-matrix) δείχνει ποιες εφαρμογές υποστηρίζουν ποιες επεκτάσεις, οπότε ελέγξτε τη δική σας πριν βασιστείτε σε οποιοδήποτε από τα δύο χαρακτηριστικά.
</Callout>

### Όταν ένας διακομιστής φέρνει τη δική του διεπαφή

Μέχρι τώρα, κάθε εργαλείο σε αυτό το κεφάλαιο απαντούσε με λέξεις ή δεδομένα. Μια αναζήτηση επιστρέφει αριθμούς ζητημάτων, μια εξαγωγή επιστρέφει ένα αρχείο, και η κεντρική εφαρμογή αποφασίζει πώς θα δείξει το αποτέλεσμα, συνήθως ως κείμενο μέσα στη συνομιλία. Ακόμη και μια φόρμα elicitation τη σχεδιάζει η κεντρική εφαρμογή, με βάση μια σύντομη περιγραφή που στέλνει ο διακομιστής. Για μια πρόταση ή μια σύντομη λίστα αυτό αρκεί. Για έναν πίνακα ελέγχου πωλήσεων, έναν πίνακα έργου ή ένα μεγάλο έγγραφο αρκεί πολύ λιγότερο, γιατί εκεί η απάντηση είναι κάτι που θέλετε να δείτε, να ταξινομήσετε και να αλλάξετε με τα δικά σας χέρια, και αλλιώς κάθε μικρή διόρθωση θα κόστιζε ένα ακόμη μήνυμα.

Η επέκταση **MCP Apps** επιτρέπει σε έναν διακομιστή να φέρει τη δική του διεπαφή. Ένα εργαλείο μπορεί να παραπέμπει σε έναν πόρο διεπαφής: μια μικρή ιστοσελίδα που ο διακομιστής προσφέρει σε μια διεύθυνση που ξεκινά με `ui://`. Όταν το εργαλείο εκτελείται, η κεντρική εφαρμογή φέρνει αυτή τη σελίδα και τη δείχνει μέσα στη συνομιλία, συνήθως σε ένα απομονωμένο πλαίσιο (sandbox) που την κρατά χωριστά από την υπόλοιπη εφαρμογή. Από εκεί και πέρα, η σελίδα και η κεντρική εφαρμογή μιλούν μέσα από ένα στενό κανάλι μηνυμάτων. Η προβολή μπορεί να δείξει τα αποτελέσματα του εργαλείου, να ζητήσει νέες κλήσεις εργαλείων και να ενημερώσει το μοντέλο για ό,τι μόλις έκανε ο άνθρωπος. Η [επισκόπηση του MCP Apps](https://modelcontextprotocol.io/extensions/apps/overview) περιγράφει τον μηχανισμό αναλυτικά. Έτσι, ένας πίνακας ελέγχου, ένας πίνακας εργασιών, ένας καμβάς σχεδίασης ή ένας επεξεργαστής εγγράφων μπορεί να εμφανιστεί μέσα στην ίδια την εφαρμογή AI, και το μοντέλο με τον άνθρωπο δουλεύουν πάνω στο ίδιο πράγμα, στην ίδια προβολή.

Η ιδέα δεν γεννήθηκε σε μία μόνο εταιρεία. Το κοινοτικό έργο [MCP-UI](https://mcpui.dev/) εξερεύνησε νωρίς τις διαδραστικές προβολές για διακομιστές MCP, και στις 6 Οκτωβρίου 2025 η OpenAI [παρουσίασε τις εφαρμογές στο ChatGPT](https://openai.com/index/introducing-apps-in-chatgpt/) μαζί με ένα Apps SDK χτισμένο πάνω στο MCP. Τον επόμενο μήνα, το έργο MCP πρότεινε ένα κοινό πρότυπο, πατώντας και στα δύο, και στις 26 Ιανουαρίου 2026 [ανακοίνωσε το MCP Apps](https://blog.modelcontextprotocol.io/posts/2026-01-26-mcp-apps/) ως την πρώτη επίσημη επέκτασή του. Το Claude, το ChatGPT, το Goose και το Visual Studio Code ήταν ανάμεσα στις πρώτες κεντρικές εφαρμογές που την υποστήριξαν. Η [τρέχουσα τεκμηρίωση της OpenAI](https://developers.openai.com/plugins/build/chatgpt-ui) αναφέρει ότι το ChatGPT υλοποιεί το ανοιχτό πρότυπο, οπότε η ίδια διεπαφή μπορεί να λειτουργεί και σε άλλες συμβατές κεντρικές εφαρμογές. Αυτή είναι η πρακτική αξία μιας ανοιχτής επέκτασης: μια εφαρμογή χτισμένη πάνω της δεν είναι δεμένη με μία μόνο εφαρμογή AI. Ο [πίνακας υποστήριξης πελατών](https://modelcontextprotocol.io/extensions/client-matrix) δείχνει ποιες εφαρμογές την υποστηρίζουν σήμερα.

Οι διαδραστικοί connectors της Anthropic στο Claude δείχνουν πόσο μακριά μπορεί να φτάσει η ιδέα. [Κυκλοφόρησαν](https://claude.com/resources/articles/interactive-tools-in-claude) τον ίδιο εκείνο Ιανουάριο ως μικρές προβολές μέσα στη συνομιλία: ένα μήνυμα Slack για να το ελέγξετε πριν το στείλετε, ένα χρονοδιάγραμμα του Asana, ένα γράφημα από το Hex. Στις 10 Νοεμβρίου 2026, η Anthropic τους [επέκτεινε](https://claude.com/resources/articles/interactive-connectors-full-tool): όπου ένας connector το υποστηρίζει, ολόκληρο το εργαλείο μπορεί πλέον να ανοίξει δίπλα στη συνομιλία ή σε πλήρη οθόνη. Για το Confluence ή το Notion, αυτό σημαίνει τον πλήρη επεξεργαστή, συνδεδεμένο με τον δικό σας λογαριασμό, αντί για μια περιορισμένη προεπισκόπηση. Μπορείτε να ανοίξετε ένα αρχείο στο Box και να συγκρίνετε εκδόσεις πριν κρατήσετε μια αλλαγή, να ρετουσάρετε μια φωτογραφία ή να αποκρύψετε στοιχεία σε ένα PDF με το Adobe, ή να δουλέψετε σε ένα σχέδιο στο Canva. Όταν ζητάτε από το Claude να αλλάξει κάτι, οι επεξεργασίες του εμφανίζονται στο εργαλείο καθώς τις κάνει, και εγκρίνετε αυτές τις ενέργειες με τον ίδιο τρόπο που εγκρίνετε κάθε άλλη ενέργεια ενός connector. Σύμφωνα με την Anthropic, όλα αυτά λειτουργούν πάνω στο MCP Apps, ενώ νεότερα κομμάτια της επέκτασης, όπως τα εργαλεία εφαρμογών και οι ενσωματωμένοι ιστότοποι, είναι σε δημόσια προεπισκόπηση για προγραμματιστές.

Αυτό που αλλάζει περισσότερο είναι η μορφή της δουλειάς. Αντί να διαβάζετε την αναφορά του μοντέλου για όσα έκανε, τα βλέπετε να γίνονται, μέσα σε ένα εργαλείο που ήδη γνωρίζετε. Μπορείτε να κάνετε μια αλλαγή μόνοι σας ή να τη ζητήσετε από το μοντέλο, και οι δύο καταλήγουν στην ίδια σελίδα, οπότε μια διόρθωση είναι συχνά ένα κλικ αντί για μια ακόμη παράγραφο εξηγήσεων. Αλλάζουν και τα prompts σας: δεν χρειάζεται να περιγράψετε τι υπάρχει στην οθόνη όταν το βλέπετε και οι δύο. Κάποια πράγματα όμως μένουν ίδια. Η [σελίδα βοήθειας του Claude](https://support.claude.com/en/articles/13454812-use-interactive-connectors-in-claude) σημειώνει ότι το μοντέλο μπορεί να κάνει μόνο τις ενέργειες που έχει διαθέσει ο δημιουργός του connector, και ότι η προβολή χρησιμοποιεί τα ίδια δικαιώματα που δώσατε όταν συνδέσατε το εργαλείο. Ένα πλουσιότερο παράθυρο δεν είναι μια φαρδύτερη πόρτα.

<Callout type="warning" title="Μια διεπαφή από διακομιστή παραμένει κώδικας από διακομιστή">
Ένα MCP App είναι κώδικας που δεν γράψατε εσείς και που τρέχει μέσα σε μια εφαρμογή που εμπιστεύεστε. Η επέκταση έχει σχεδιαστεί με αυτό κατά νου: οι προβολές τρέχουν σε απομονωμένα πλαίσια, οι διακομιστές δηλώνουν εκ των προτέρων ποιους εξωτερικούς τομείς χρειάζονται, οι κεντρικές εφαρμογές μπορούν να ελέγξουν μια προβολή πριν τη δείξουν, τα μηνύματα ανάμεσα στην προβολή και την κεντρική εφαρμογή μπορούν να καταγράφονται, και οι κεντρικές εφαρμογές μπορούν να ζητούν έγκριση πριν από μια κλήση εργαλείου που ξεκινά από την προβολή. Αυτά τα επίπεδα περιορίζουν το πού μπορεί να φτάσει ο κώδικας. Δεν κάνουν αληθινό αυτό που δείχνει. Το κείμενο μιας προβολής μπορεί να παραπλανά ή να κουβαλά μια ενσωματωμένη εντολή, όπως κάθε έγγραφο. Γι' αυτό η διεπαφή ανήκει στην ίδια απόφαση με τον ίδιο τον διακομιστή, και, όπως δείχνει μια επόμενη ενότητα, η σύνδεση είναι ήδη ζήτημα εμπιστοσύνης. Η υποστήριξη διαφέρει επίσης από εφαρμογή σε εφαρμογή, και κάθε κεντρική εφαρμογή αποφασίζει πόσο μέρος της επέκτασης θα υλοποιήσει, οπότε ελέγξτε τι κάνει η δική σας πριν βασιστείτε σε αυτό.
</Callout>

### Εύρεση διακομιστή και σύνδεση μία φορά

Πριν ένας πράκτορας μπορέσει να χρησιμοποιήσει έναν απομακρυσμένο διακομιστή, κάποιος πρέπει να τον βρει, να μάθει πώς συνδέεται κανείς και να συνδεθεί στον λογαριασμό. Για πολύ καιρό αυτό σήμαινε αντιγραφή μιας διεύθυνσης από ένα README, μαντεψιά για το ποιο transport χρειάζεται και επανάληψη της ρύθμισης σε κάθε εφαρμογή. Τώρα έρχονται δύο είδη βοήθειας: πληροφορίες που ένας πελάτης μπορεί να διαβάσει **πριν** συνδεθεί, και συνδέσεις που ρυθμίζετε **μία φορά** και ξαναχρησιμοποιείτε.

Από την πλευρά της ανακάλυψης, η επέκταση **Server Cards** του MCP ([SEP-2127](https://modelcontextprotocol.io/seps/2127-mcp-server-cards)) οριστικοποιήθηκε στις 6 Οκτωβρίου 2026. Περιγράφει ένα μικρό, στατικό έγγραφο για έναν απομακρυσμένο διακομιστή: το όνομά του, τα endpoints και τα transports του, και τις εκδόσεις του πρωτοκόλλου που υποστηρίζει. Ένας ιστότοπος μπορεί να καταγράψει τις κάρτες του σε έναν κατάλογο AI στη διεύθυνση `/.well-known/ai-catalog.json`, ώστε ένας πελάτης που τον κατευθύνουμε σε ένα domain να μαθαίνει πού και πώς να συνδεθεί χωρίς χειροκίνητη ρύθμιση. Η κάρτα αφήνει σκόπιμα έξω τη λίστα εργαλείων, επειδή τα εργαλεία ενός διακομιστή μπορεί να αλλάζουν ανάλογα με τον συνδεδεμένο χρήστη. Αυτά εξακολουθούν να έρχονται από το `tools/list` μετά τη σύνδεση.

Από την πλευρά της σύνδεσης, το GitHub άρχισε στις 28 Οκτωβρίου 2026 να διαθέτει σε δημόσια προεπισκόπηση τους [διακομιστές MCP επαληθευμένους από το GitHub](https://github.blog/changelog/2026-10-28-connect-your-tools-to-copilot-without-all-the-setup/), τους οποίους αποκαλεί και connectors. Συνδέεστε μία φορά σε μια υπηρεσία όπως το Slack ή το Sentry, και η σύνδεση λειτουργεί στην εφαρμογή Copilot, στο Copilot CLI, στο VS Code, στο Copilot στο cloud και στο GitHub Mobile.

Και τα εργαλεία δεν είναι μόνο υπηρεσίες ιστού. Την ίδια μέρα, στο Android Dev Summit, η Google [ανακοίνωσε](https://developer.android.com/blog/posts/build-it-your-way-a-next-era-of-android-development) ότι το **AppFunctions**, που το περιγράφει ως το ενιαίο επίπεδο κλήσης εργαλείων του Android, είναι πλέον σε beta. Μέσω του Android MCP, μια εφαρμογή στο τηλέφωνό σας μπορεί να προσφέρει λειτουργίες, όπως τη δημιουργία μιας σημείωσης ή την αποστολή ενός μηνύματος, σε δικό της πράκτορα στη συσκευή ή σε πράκτορες του συστήματος, χωρίς να χρειαστεί κανείς να ανοίξει την εφαρμογή.

Αυτό μας φέρνει πίσω σε κάτι που είπαμε νωρίτερα: ο **connector** είναι όρος προϊόντος. Μια κάρτα διακομιστή, ένα σήμα επαλήθευσης και μια ενιαία σύνδεση κάνουν τη ρύθμιση πιο εύκολη και σας βοηθούν να εμπιστευτείτε *με ποιον* συνδέεστε. Δεν αποφασίζουν *τι* παραχωρείτε. Εσείς εξακολουθείτε να επιλέγετε ποιον λογαριασμό θα συνδέσετε, ποια δικαιώματα θα επιτρέψετε και ποιες ενέργειες πρέπει να περιμένουν έγκριση. Ούτε τα μεταδεδομένα ανακάλυψης ούτε η επαλήθευση αντικαθιστούν τον έλεγχο του τι μπορούν πραγματικά να κάνουν τα εργαλεία, μόλις εμφανιστούν στη λίστα.

### Όταν κανείς δεν ψάχνει τον διακομιστή

Όλα τα παραπάνω προϋποθέτουν ότι κάποιος ψάχνει πραγματικά τον διακομιστή, είτε ένας άνθρωπος που ξεφυλλίζει έναν κατάλογο είτε ένας client που διαβάζει μια κάρτα διακομιστή. Συχνά όμως κανείς δεν το κάνει. Λέτε σε έναν πράκτορα προγραμματισμού «στήσε ένα GitHub MCP», και ο πράκτορας πρέπει να διαλέξει μόνος του το πακέτο. Αν καταφύγει σε ένα όνομα που θυμάται και όχι σε ένα που έχει ελέγξει, η επιλογή προέρχεται από τα δεδομένα εκπαίδευσης του μοντέλου, και αυτά τα δεδομένα είναι ένα στιγμιότυπο μιας στιγμής που έχει ήδη περάσει. Από τότε, ο ιδιοκτήτης μιας υπηρεσίας μπορεί να έχει αντικαταστήσει τον διακομιστή ή να τον έχει αρχειοθετήσει, και το μοντέλο δεν έχει κανέναν τρόπο να το μάθει.

Ερευνητές της Glow Labs (Glow Security) [περιέγραψαν ακριβώς αυτό](https://www.helpnetsecurity.com/2026/11/03/mcphantom-deprecated-mcp-servers/) τον Νοέμβριο του 2026, αφού εξέτασαν πραγματικές καταγραφές από συνεδρίες προγραμματισμού, και ονόμασαν το φαινόμενο MCPhantom. Στις συνεδρίες όπου ένας πράκτορας εγκατέστησε ή πρότεινε έναν παρωχημένο διακομιστή MCP, ο πράκτορας φαίνεται ότι συμπλήρωσε το όνομα του πακέτου από τα δεδομένα εκπαίδευσης στο 98% των περιπτώσεων· στο υπόλοιπο 2%, ο χρήστης είχε ζητήσει ο ίδιος το παλιό πακέτο με το όνομά του. Στο παράδειγμα με το GitHub, ο πράκτορας προσπέρασε τον διακομιστή που συντηρεί η ίδια η GitHub και προτίμησε έναν αρχειοθετημένο διακομιστή αναφοράς που θυμόταν. Δεν έφταιγε ένα μόνο προϊόν: το φαινόμενο εμφανίστηκε σε αρκετά harnesses, ανάμεσά τους τα Claude Code, Cursor και Codex CLI, και με μοντέλα από διάφορους παρόχους. Οι ερευνητές βρήκαν επίσης τέσσερα κενά ασφαλείας υψηλής σοβαρότητας σε αυτούς τους αρχειοθετημένους διακομιστές. Το σοβαρότερο είναι ένα σφάλμα απομακρυσμένης εκτέλεσης κώδικα στον διακομιστή Puppeteer, στο οποίο μπορεί να φτάσει κανείς μέσω μιας έγχυσης prompt (prompt injection). Επειδή τα αποθετήρια είναι αρχειοθετημένα, διορθώσεις δεν πρόκειται να έρθουν, αν και η αναφορά σημειώνει ότι δεν είχε παρατηρηθεί κάποια εκμετάλλευση.

Δύο λεπτομέρειες κάνουν το πρόβλημα εύκολο να περάσει απαρατήρητο. Ο έλεγχος του πακέτου δεν αρκεί πάντα: σε μία συνεδρία ο πράκτορας είδε στο npm την ένδειξη «This package is deprecated», το εγκατέστησε παρ' όλα αυτά και δεν είπε τίποτα στον χρήστη. Και επειδή αυτοί οι διακομιστές συνήθως εκτελούνται μέσω `npx`, δεν εμφανίζονται ποτέ σε αρχείο εξαρτήσεων, οπότε τίποτα στο έργο δεν καταγράφει ότι βρίσκονται εκεί. Όπως το έθεσε ένας από τους ερευνητές: «Η μνήμη του μοντέλου είναι πλέον ένας διαχειριστής πακέτων που δεν μαθαίνει ποτέ τι έχει καταργηθεί».

<Callout type="warning" title="Και η εγκατάσταση είναι ενέργεια">
Πριν ένας πράκτορας προσθέσει έναν διακομιστή, ρωτήστε ποιο πακέτο επέλεξε και από πού προέρχεται. Προτιμήστε τον επίσημο διακομιστή του ιδιοκτήτη της υπηρεσίας όταν υπάρχει, ελέγξτε ότι εξακολουθεί να συντηρείται και δεν είναι παρωχημένος ή αρχειοθετημένος, και καταλήξτε σε έναν διακομιστή ανά υπηρεσία. Αντιμετωπίστε την εγκατάσταση ως κάτι που εγκρίνετε εσείς, όπως κάθε άλλη ενέργεια του πράκτορα. Το πιο απλό απ' όλα είναι να ονομάσετε τον διακομιστή που θέλετε μέσα στο ίδιο το prompt, ώστε ο πράκτορας να μην έχει τίποτα να συμπληρώσει από μνήμης.
</Callout>

### Η σύνδεση είναι ήδη ζήτημα εμπιστοσύνης

Το MCPhantom αφορά την επιλογή του λάθος διακομιστή. Από την άλλη πλευρά αυτής της επιλογής περιμένει ένας πιο αθόρυβος κίνδυνος: ακόμη κι όταν διαλέγετε έναν απομακρυσμένο διακομιστή με προσοχή, η ίδια η σύνδεση μαζί του μπορεί ήδη να κάνει ζημιά. Ένας απομακρυσμένος διακομιστής τρέχει στο μηχάνημα κάποιου άλλου, άρα ο κώδικάς του δεν φτάνει ποτέ στο δικό σας, και γι' αυτό μια πρώτη σύνδεση μοιάζει με μια ματιά χωρίς συνέπειες. Δεν είναι ακριβώς έτσι. Ο client σας εξακολουθεί να τρέχει στο δικό σας μηχάνημα, και διαβάζει και επεξεργάζεται ό,τι στέλνει πίσω ο διακομιστής, μαζί και τις διευθύνσεις που δίνει ο διακομιστής όταν σας ζητά να συνδεθείτε στον λογαριασμό σας.

Στις 5 Νοεμβρίου 2026, η Pillar Security [έδειξε πόσο σημαντικό είναι αυτό](https://www.pillar.security/blog/inspecting-the-inspector-rce-in-mcps-official-debugging-tool). Αντικείμενο της έρευνας ήταν το MCP Inspector (`@modelcontextprotocol/inspector`), το επίσημο εργαλείο αποσφαλμάτωσης του έργου MCP. Οι προγραμματιστές το στρέφουν σε τοπικούς και απομακρυσμένους διακομιστές που δεν εμπιστεύονται ακόμη, για να δουν τα εργαλεία, τους πόρους και τα prompts τους πριν αφήσουν έναν πραγματικό πράκτορα να τους πλησιάσει. Σε Windows και WSL, οι εκδόσεις του Inspector πριν από την 2.12.0 μπορούσαν να εξαναγκαστούν να εκτελέσουν αυθαίρετο κώδικα κατά τη σύνδεση μέσω OAuth με έναν απομακρυσμένο διακομιστή, πριν εμφανιστεί στη λίστα έστω και ένα εργαλείο και χωρίς να εγκρίνει κανείς τίποτα.

Η αλυσίδα είναι σύντομη, και κάθε κρίκος της μοιάζει αθώος αν τον δει κανείς μόνο του. Όταν ένας απομακρυσμένος διακομιστής ζητά από τον client να συνδεθεί, δηλώνει το δικό του `authorization_endpoint`, τη διεύθυνση της σελίδας σύνδεσής του, και αυτή η διεύθυνση είναι μια συμβολοσειρά που επιλέγει ο ίδιος ο διακομιστής. Ο client την ανοίγει αυτόματα με το `open`, ένα δημοφιλές πακέτο npm για το άνοιγμα του προγράμματος περιήγησης. Σε Windows και WSL, οι εκδόσεις του `open` πριν από την 11.0.0 έβαζαν τη διεύθυνση μέσα σε μια εντολή PowerShell χωρίς διαφυγή (escaping), κι έτσι το PowerShell μπορούσε να εκτελέσει κώδικα κρυμμένο σε κάτι που κατά τα άλλα ήταν ένα απολύτως έγκυρο https URL. Ο κώδικας έτρεχε ενώ ο προγραμματιστής απλώς συνδεόταν, πριν καν ανοίξει το πρόγραμμα περιήγησης.

Οι συντηρητές αποδέχτηκαν την αναφορά και διόρθωσαν το πρόβλημα στο Inspector 2.12.0, που κυκλοφόρησε στις 21 Οκτωβρίου 2026: η έκδοση περνά στο `open` 11 και φροντίζει ώστε το URL που ανοίγει να είναι ακριβώς εκείνο που ελέγχθηκε. Δημοσίευσαν επίσης την ανακοίνωση ασφαλείας [GHSA-q978-78c7-phqw](https://github.com/modelcontextprotocol/inspector/security/advisories/GHSA-q978-78c7-phqw). Το Inspector δεν ήταν μόνο του. Δύο εβδομάδες νωρίτερα, η Pillar είχε [περιγράψει την ίδια αλυσίδα](https://www.pillar.security/blog/open-and-shut-remote-code-execution-in-opencode-via-mcp-oauth) στον πράκτορα προγραμματισμού OpenCode (`opencode-ai`). Επειδή η βασική αιτία βρίσκεται στον τρόπο με τον οποίο και τα δύο εργαλεία έδιναν στο `open` τη διεύθυνση ενός διακομιστή, μία μόνο εγγραφή, η CVE-2026-119025, καλύπτει πλέον μαζί το `open`, το Inspector και το OpenCode.

Το δίδαγμα πηγαίνει πέρα από ένα μεμονωμένο σφάλμα. Το Inspector υπάρχει για να μπορείτε να εξετάσετε έναν εχθρικό διακομιστή χωρίς να πάθετε κακό. Αντιμετωπίζοντας έναν εχθρικό απομακρυσμένο διακομιστή ως πραγματικό σενάριο για το δικό του εργαλείο αναφοράς, διορθώνοντας το σφάλμα και δημοσιεύοντας ανακοίνωση, το έργο MCP έθεσε μια προσδοκία για κάθε client που υλοποιεί την ίδια ροή OAuth: ένας απομακρυσμένος διακομιστής MCP είναι μη έμπιστη είσοδος. Ούτε χρειάζεται ένας διακομιστής να είναι κακόβουλος από την αρχή. Ένα όνομα σχεδόν ίδιο με κάποιο άλλο, ένας τομέας (domain) που έληξε ή μια μεταγενέστερη κατάληψη μπορούν να βάλουν μια κακόβουλη απάντηση πίσω από μια διεύθυνση που κάποτε εμπιστευόσασταν, και αυτή η απάντηση φτάνει ξανά σε κάθε σύνδεση. Οι κάρτες διακομιστή και τα σήματα επαλήθευσης που είδαμε νωρίτερα σας βοηθούν να διαλέξετε *με ποιον* συνδέεστε. Δεν αλλάζουν όμως το τι κάνει ο client σας με την απάντηση.

<Callout type="warning" title="Η χειραψία είναι κι αυτή μέρος του ορίου εμπιστοσύνης">
Πριν συνδεθείτε σε έναν απομακρυσμένο διακομιστή, ειδικά σε κάποιον που ακόμη ελέγχετε, να ξέρετε ποιον client χρησιμοποιείτε και σε ποια έκδοση, και να τον κρατάτε ενημερωμένο. Σε Windows και WSL, αυτό σημαίνει MCP Inspector 2.12.0 ή νεότερο, OpenCode 1.18.33 ή νεότερο και `open` 11.0.0 ή νεότερο, αν το χρησιμοποιεί ο δικός σας κώδικας. Όταν ζητάτε από έναν πράκτορα να προσθέσει ή να δοκιμάσει έναν διακομιστή για λογαριασμό σας, client είναι το harness του, οπότε ισχύουν οι ίδιες ερωτήσεις. Πάνω απ' όλα, αντιμετωπίστε τη σύνδεση ως απόφαση και όχι ως ματιά χωρίς συνέπειες: η χειραψία της σύνδεσης τρέχει ήδη στο μηχάνημά σας, πριν εμφανιστεί το πρώτο εργαλείο.
</Callout>

## Προτροπές για έναν πράκτορα με εργαλεία

Πείτε στον πράκτορα ποιες πληροφορίες να αναζητήσει, πώς να τις χρησιμοποιήσει και ποιες ενέργειες περιμένετε. Μην θεωρείτε δεδομένο ότι υπάρχει σύνδεση ή ότι ένα εργαλείο υποστηρίζει όλες τις λειτουργίες της υπηρεσίας.

Ετοίμασε προσχέδιο επόμενου θέματος αν χρειάζεται, αλλά ρώτησε πριν το δημιουργήσεις. Αν η σύνδεση ή το απαραίτητο εργαλείο δεν είναι διαθέσιμα, εξήγησε τι λείπει. Μια επαναχρησιμοποιήσιμη δεξιότητα διαλογής μπορεί να προσθέσει τη μέθοδο: έλεγχο διπλοτύπων, σύγκριση βημάτων αναπαραγωγής, χρήση του προτύπου θεμάτων του έργου και αναφορά ανεπίλυτων ερωτημάτων. Το εργαλείο παρέχει τη λειτουργία. Η δεξιότητα εξηγεί πώς να τη χρησιμοποιήσετε καλά.

Η έξοδος εργαλείου χρειάζεται ακόμη κρίση. Ένα σχόλιο θέματος, έγγραφο ή αποτέλεσμα αναζήτησης μπορεί να περιέχει λάθη ή κείμενο που μοιάζει με οδηγία. Αντιμετωπίστε το περιεχόμενο που ανακτήθηκε ως δεδομένα, χωρίς να του επιτρέπετε να αλλάξει το αίτημα του χρήστη ή τους κανόνες της εφαρμογής. Η υποστήριξη MCP μόνη της δεν κάνει έναν διακομιστή ή το περιεχόμενό του αξιόπιστο.

Αν αποτύχει η ανάγνωση, ο πράκτορας μπορεί να αναφέρει το σφάλμα ή να δοκιμάσει λογική εναλλακτική. Αν η εγγραφή λήξει λόγω χρόνου, πρέπει να ελέγξει αν έγινε η αλλαγή πριν την επαναλάβει. Διαφορετικά, η νέα προσπάθεια μπορεί να δημιουργήσει διπλό θέμα. Τα διαπιστευτήρια ανήκουν στις ρυθμίσεις σύνδεσης της ενσωμάτωσης, όχι στην προτροπή της εργασίας. Αυτοί οι κανόνες έχουν ακόμη μεγαλύτερη σημασία όταν ένα bot χρησιμοποιεί εργαλεία βάσει χρονοδιαγράμματος ενώ λείπετε, όπως περιγράφεται στο κεφάλαιο [Πάντα Ενεργά Bots](/book/28-persistent-bots).
