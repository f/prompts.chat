Ζητάτε από έναν πράκτορα να βρει τα ανοιχτά bugs του έργου σας και να ετοιμάσει ένα προσχέδιο για θέμα παρακολούθησης. Για να το κάνει, δεν αρκούν οι καλές οδηγίες. Χρειάζεται τρόπο να φτάσει στο σύστημα παρακολούθησης θεμάτων, να διαβάσει τα σωστά δεδομένα και πιθανώς να δημιουργήσει κάτι εκεί.

Εδώ χρειάζονται τα **εργαλεία**, οι **συνδέσεις υπηρεσιών (connectors)** και το **MCP**. Σχετίζονται, αλλά περιγράφουν διαφορετικά μέρη της εγκατάστασης.

## Τι περιέχει ένα εργαλείο

Ένα εργαλείο συνήθως έχει **όνομα**, **περιγραφή**, **σχήμα εισόδου** και μια υλοποίηση που κάνει τη δουλειά. Η περιγραφή βοηθά το μοντέλο να αποφασίσει πότε θα το χρησιμοποιήσει. Το σχήμα περιγράφει τα ορίσματα που δέχεται.

Ακολουθεί ένας μικρός ορισμός φανταστικού εργαλείου MCP:

<Collapsible title="Δείτε τον ορισμό του search_issues">

```json
{
  "name": "search_issues",
  "description": "Αναζήτηση θεμάτων στο συνδεδεμένο έργο. Αυτό το εργαλείο μόνο διαβάζει δεδομένα.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": { "type": "string" },
      "limit": { "type": "integer", "minimum": 1, "maximum": 20 }
    },
    "required": ["query"],
    "additionalProperties": false
  }
}
```

</Collapsible>

Το μοντέλο μπορεί να ζητήσει το `search_issues` με `{"query": "ανοιχτά bugs", "limit": 3}`. Η εφαρμογή που το περιβάλλει στέλνει το αίτημα στην υλοποίηση. Η υλοποίηση ρωτά το σύστημα θεμάτων και επιστρέφει αποτελέσματα ή σφάλμα.

Το όνομα και το σχήμα δεν εκτελούν τίποτα από μόνα τους. Η υλοποίηση πρέπει να επικυρώσει τις εισόδους, να ελέγξει την πρόσβαση και να εκτελέσει την πραγματική λειτουργία. Η απάντηση του εργαλείου είναι επίσης ξεχωριστή από την τελική απάντηση του μοντέλου: μπορεί να περιέχει ID και τίτλους θεμάτων, τα οποία μετά συνοψίζει το μοντέλο. Η [προδιαγραφή εργαλείων MCP](https://modelcontextprotocol.io/specification/latest/server/tools) περιγράφει πώς τα εργαλεία παρέχουν αυτές τις λειτουργίες.

<Callout type="info" title="Το αίτημα δεν είναι αποτέλεσμα">
Το «Θα δημιουργήσω ένα θέμα» είναι δήλωση. Η κλήση εργαλείου ζητά την εκτέλεση της λειτουργίας. Μια επιτυχής απάντηση με το ID του νέου θέματος είναι στοιχείο ότι η λειτουργία έγινε. Κρατήστε αυτά τα τρία πράγματα ξεχωριστά.
</Callout>

## Τι προσθέτει ένας connector

Ένας connector συγκεντρώνει την ενσωμάτωση με ένα συγκεκριμένο σύστημα. Μπορεί να χειρίζεται τη σύνδεση χρήστη, την επιλογή λογαριασμού ή χώρου εργασίας, την εύρεση δεδομένων και την παροχή υποστηριζόμενων ενεργειών ως εργαλεία. Μερικοί connectors μόνο αναζητούν ή διαβάζουν. Άλλοι υποστηρίζουν και εγγραφές.

**Ο connector είναι όρος προϊόντος, όχι ένα ενιαίο τεχνικό πρότυπο.** Ένας connector μπορεί να καλεί απευθείας το API μιας υπηρεσίας. Άλλος μπορεί να χρησιμοποιεί διακομιστή MCP. Ένας τρίτος μπορεί να ψάχνει σε ευρετήριο από συγχρονισμένα έγγραφα. Ελέγξτε τι υποστηρίζει η συγκεκριμένη ενσωμάτωση. Η [επισκόπηση connectors](https://learn.microsoft.com/en-us/azure/connectors/introduction) της Microsoft δίνει ένα παράδειγμα ενσωματώσεων γύρω από API.

Η σύνδεση λογαριασμού δεν σημαίνει ότι ο πράκτορας βλέπει κάθε αρχείο, φορτώνει όλα τα δεδομένα σας στο πλαίσιό του ή έχει δικαίωμα για κάθε ενέργεια. Η πρόσβαση εξαρτάται από τον λογαριασμό, τα ρυθμισμένα πεδία δικαιωμάτων, την εφαρμογή και τα δικαιώματα της ίδιας της υπηρεσίας. Τα αποτελέσματα αναζήτησης μπορεί επίσης να προέρχονται από ευρετήριο παλαιότερο από τα αρχικά έγγραφα.

Για το σύστημα θεμάτων, ξεχωρίστε τα εξής: Έχει ρυθμιστεί σύνδεση; Σε ποιο έργο μπορεί να έχει πρόσβαση; Μπορεί μόνο να διαβάζει ή και να δημιουργεί θέματα;

## Τι τυποποιεί το MCP

Το **MCP** σημαίνει **Model Context Protocol**. Ορίζει έναν κοινό τρόπο επικοινωνίας ανάμεσα σε εφαρμογές AI και εξωτερικούς παρόχους δυνατοτήτων. Δεν αντικαθιστά το API μιας υπηρεσίας. Ένας διακομιστής MCP μπορεί να χρησιμοποιεί αυτό το API εσωτερικά.

Η [αρχιτεκτονική MCP](https://modelcontextprotocol.io/docs/learn/architecture) έχει τρεις βασικούς ρόλους:

  { label: "Πελάτης (client)", description: "Το μέρος μέσα στην κεντρική εφαρμογή που διατηρεί σύνδεση με έναν διακομιστή MCP.", color: "green" },

Για μια κλήση εργαλείου, ο πελάτης μπορεί να βρει τα εργαλεία του διακομιστή με το `tools/list`. Η εφαρμογή κάνει τους σχετικούς ορισμούς εργαλείων διαθέσιμους στο μοντέλο. Το μοντέλο δεν χρειάζεται να ανοίξει μόνο του σύνδεση δικτύου. Η εφαρμογή και η υλοποίηση MCP χειρίζονται την επικοινωνία. Η συμβατότητα όμως παραμένει σημαντική: η κεντρική εφαρμογή και ο διακομιστής πρέπει να υποστηρίζουν τις δυνατότητες που θέλετε. Η εύρεση ενός εργαλείου δεν εγγυάται άδεια εκτέλεσης. Οι έλεγχοι πρόσβασης εξακολουθούν να ισχύουν.

### Το MCP προσφέρει περισσότερα από εργαλεία

Το MCP ορίζει επίσης **πόρους** και **προτροπές**. Αυτές οι λέξεις έχουν συγκεκριμένες σημασίες στο πρωτόκολλο:

<InfoGrid columns={3} items={[

  { label: "Πόροι", description: "Δεδομένα που η εφαρμογή μπορεί να διαθέσει ως πλαίσιο. Παράδειγμα: οδηγός έργου που αναγνωρίζεται από URI.", color: "green" },
  { label: "Προτροπές", description: "Επαναχρησιμοποιήσιμα πρότυπα μηνυμάτων που επιλέγουν οι χρήστες, με προαιρετικά ορίσματα. Παράδειγμα: σύνταξη αναφοράς διαλογής θεμάτων.", color: "amber" }

Ο [οδηγός εννοιών διακομιστή MCP](https://modelcontextprotocol.io/docs/learn/server-concepts) περιγράφει τα εργαλεία ως ελεγχόμενα από το μοντέλο, τους πόρους από την εφαρμογή και τις προτροπές από τον χρήστη. Αυτά περιγράφουν τους προβλεπόμενους τρόπους αλληλεπίδρασης. Δεν αφαιρούν τους ελέγχους δικαιωμάτων της εφαρμογής.

Ένα πρότυπο προτροπής MCP δεν είναι αυτόματα δεξιότητα. Μια δεξιότητα μπορεί να συγκεντρώνει μεγαλύτερη διαδικασία, υλικό αναφοράς και σενάρια. Μπορεί να λέει στον πράκτορα πώς να χρησιμοποιεί εργαλεία από MCP, έναν άμεσο connector ή τοπικές συναρτήσεις.

### Οι δεξιότητες μπορούν να έρχονται μαζί με τον διακομιστή

Μέχρι πρόσφατα, αυτά τα δύο κομμάτια έφταναν συνήθως χωριστά. Ένας διακομιστής μπορούσε να δώσει στον πράκτορα τα εργαλεία του, αλλά η τεχνογνωσία για να τα χρησιμοποιεί σωστά βρισκόταν αλλού: σε μια δεξιότητα που εγκαθίστατο ξεχωριστά, σε ένα README ή στην προτροπή του ίδιου του χρήστη. Όταν η υπηρεσία άλλαζε, αυτές οι οδηγίες μπορούσαν να μείνουν πίσω χωρίς να το καταλάβει κανείς.

Η επίσημη **επέκταση Skills** του MCP, που οριστικοποιήθηκε τον Σεπτέμβριο του 2026, κλείνει μεγάλο μέρος αυτού του κενού. Ένας διακομιστής μπορεί πλέον να προσφέρει όχι μόνο τα εργαλεία του αλλά και τις δεξιότητες που εξηγούν πώς να χρησιμοποιούνται, γραμμένες στην ίδια μορφή `SKILL.md` που περιγράφεται στο κεφάλαιο [Πράκτορες και Δεξιότητες](/book/25-agents-and-skills). Τα εργαλεία λένε στον πράκτορα τι μπορεί να κάνει. Οι δεξιότητες του λένε πώς να κάνει καλά τη δουλειά. Τώρα και τα δύο μπορούν να έρχονται από τον ίδιο διακομιστή, έτσι οι οδηγίες βρίσκονται δίπλα στην υπηρεσία που περιγράφουν και μπορούν να ενημερώνονται από όσους τη συντηρούν.

Ο μηχανισμός στηρίζεται σε στοιχεία που έχετε ήδη γνωρίσει. Κάθε αρχείο μιας δεξιότητας εκτίθεται ως πόρος MCP, συνήθως με URI της μορφής `skill://`. Ένας πελάτης μπορεί να απαριθμήσει τις δεξιότητες ενός διακομιστή με `skills/list`, να ανακτήσει μία με `skills/get` και να διαβάσει τα συνοδευτικά της αρχεία με `resources/read`.

Η κεντρική εφαρμογή εξακολουθεί να αποφασίζει πώς φτάνει μια δεξιότητα στο μοντέλο. Το μοντέλο μπορεί να την επιλέξει από το όνομα και την περιγραφή της, ή ο χρήστης να τη διαλέξει απευθείας. Σε κάθε περίπτωση, οι πλήρεις οδηγίες μπαίνουν στο πλαίσιο μόνο όταν χρειάζονται, και η ανάγνωση ενός αρχείου `SKILL.md` δεν ενεργοποιεί από μόνη της τη δεξιότητα.

<Callout type="warning" title="Μια δεξιότητα από διακομιστή παραμένει οδηγίες">
Μια δεξιότητα από διακομιστή είναι κείμενο που μπαίνει στο πλαίσιο του πράκτορα και μπορεί να επηρεάσει τι θα κάνει στη συνέχεια. Αξίζει λοιπόν τον ίδιο έλεγχο με τον ίδιο τον διακομιστή. Μια προσεκτική κεντρική εφαρμογή επαληθεύει το περιεχόμενο και ζητά όποια έγκριση απαιτείται πριν το φορτώσει. Όπως άλλες επίσημες επεκτάσεις του MCP, για παράδειγμα τα MCP Apps και MCP Tasks, η επέκταση Skills είναι προαιρετική: χρησιμοποιείται μόνο όταν και ο πελάτης και ο διακομιστής δηλώνουν ότι την υποστηρίζουν. Η υποστήριξη από τους πελάτες βρίσκεται ακόμη στην αρχή, οπότε ελέγξτε αν η εφαρμογή σας φορτώνει πράγματι δεξιότητες από διακομιστές πριν βασιστείτε σε αυτές.
</Callout>

## Προτροπές για έναν πράκτορα με εργαλεία

Πείτε στον πράκτορα ποιες πληροφορίες να αναζητήσει, πώς να τις χρησιμοποιήσει και ποιες ενέργειες περιμένετε. Μην θεωρείτε δεδομένο ότι υπάρχει σύνδεση ή ότι ένα εργαλείο υποστηρίζει όλες τις λειτουργίες της υπηρεσίας.

<Compare
  before={{ label: "Πάρα πολλά μένουν στην εικασία", content: "Έλεγξε τα bugs και τακτοποίησε τα πάντα." }}
  after={{ label: "Σαφές αποτέλεσμα και όρια", content: "Αναζήτησε στο συνδεδεμένο έργο ανοιχτά bugs για κενά αποτελέσματα αναζήτησης. Σύνοψε τα σχετικά θέματα και βάλε τα ID τους. Ετοίμασε προσχέδιο επόμενου θέματος αν χρειάζεται, αλλά ρώτησε πριν το δημιουργήσεις. Αν η σύνδεση ή το απαραίτητο εργαλείο δεν είναι διαθέσιμα, εξήγησε τι λείπει. Μην ισχυριστείς ότι δημιουργήθηκε θέμα χωρίς επιτυχές αποτέλεσμα εργαλείου." }}
/>

Μια επαναχρησιμοποιήσιμη δεξιότητα διαλογής μπορεί να προσθέσει τη μέθοδο: έλεγχο διπλοτύπων, σύγκριση βημάτων αναπαραγωγής, χρήση του προτύπου θεμάτων του έργου και αναφορά ανεπίλυτων ερωτημάτων. Το εργαλείο παρέχει τη λειτουργία. Η δεξιότητα εξηγεί πώς να τη χρησιμοποιήσετε καλά.

Η έξοδος εργαλείου χρειάζεται ακόμη κρίση. Ένα σχόλιο θέματος, έγγραφο ή αποτέλεσμα αναζήτησης μπορεί να περιέχει λάθη ή κείμενο που μοιάζει με οδηγία. Αντιμετωπίστε το περιεχόμενο που ανακτήθηκε ως δεδομένα, χωρίς να του επιτρέπετε να αλλάξει το αίτημα του χρήστη ή τους κανόνες της εφαρμογής. Η υποστήριξη MCP μόνη της δεν κάνει έναν διακομιστή ή το περιεχόμενό του αξιόπιστο.

Αν αποτύχει η ανάγνωση, ο πράκτορας μπορεί να αναφέρει το σφάλμα ή να δοκιμάσει λογική εναλλακτική. Αν η εγγραφή λήξει λόγω χρόνου, πρέπει να ελέγξει αν έγινε η αλλαγή πριν την επαναλάβει. Διαφορετικά, η νέα προσπάθεια μπορεί να δημιουργήσει διπλό θέμα. Τα διαπιστευτήρια ανήκουν στις ρυθμίσεις σύνδεσης της ενσωμάτωσης, όχι στην προτροπή της εργασίας. Αυτοί οι κανόνες έχουν ακόμη μεγαλύτερη σημασία όταν ένα bot χρησιμοποιεί εργαλεία βάσει χρονοδιαγράμματος ενώ λείπετε, όπως περιγράφεται στο κεφάλαιο [Πάντα Ενεργά Bots](/book/28-persistent-bots).
