Les formats de données structurées comme JSON et YAML sont essentiels pour construire des applications qui exploitent les sorties d'IA par programme. Ce chapitre présente les techniques qui permettent de générer des sorties structurées de manière fiable.

<Callout type="info" title="Du texte aux données">
JSON et YAML transforment les sorties d'IA, du texte libre, en données structurées et typées que le code peut consommer directement.
</Callout>

## Bases du prompting JSON

JSON (JavaScript Object Notation) est le format le plus courant pour les sorties d'IA destinées à un programme. Sa syntaxe stricte le rend facile à analyser, mais signifie aussi qu'une petite erreur peut casser tout votre pipeline.

### À faire et à éviter : demander du JSON

<Compare 
  before={{ label: "❌ À éviter : demande vague", content: "Donne-moi les infos utilisateur en JSON." }}
  after={{ label: "✓ À faire : montrer le schéma", content: "Extrais les infos utilisateur en JSON correspondant à ce schéma :\n\n{\n  \"nom\": \"string\",\n  \"age\": number,\n  \"email\": \"string\"\n}\n\nRetourne UNIQUEMENT du JSON valide, sans markdown." }}
/>

### Sortie JSON simple

Commencez par un schéma qui montre la structure attendue. Le modèle remplira les valeurs à partir du texte d'entrée.

```
Extrais les informations suivantes en JSON :

{
  "nom": "string",
  "age": number,
  "email": "string"
}

Texte : "Contactez Jean Dupont, 34 ans, à jean@exemple.com"
```

Sortie :
```json
{
  "nom": "Jean Dupont",
  "age": 34,
  "email": "jean@exemple.com"
}
```

### Structures JSON imbriquées

Les données réelles comportent souvent des relations imbriquées. Définissez clairement chaque niveau de votre schéma, surtout pour les tableaux d'objets.

```
Convertis cette commande en JSON :

{
  "id_commande": "string",
  "client": {
    "nom": "string",
    "email": "string"
  },
  "articles": [
    {
      "produit": "string",
      "quantite": number,
      "prix": number
    }
  ],
  "total": number
}

Commande : "Commande #12345 pour Marie Martin (marie@email.com) : 2x Widget (10€ chacun), 
1x Gadget (25€). Total : 45€"
```

### Garantir un JSON valide

<Callout type="warning" title="Source d'échec fréquente">
Les modèles enveloppent souvent le JSON dans des blocs de code markdown ou ajoutent du texte explicatif. Indiquez explicitement que vous voulez uniquement du JSON brut.
</Callout>

Ajoutez des instructions explicites :

```
CRITIQUE : Retourne UNIQUEMENT du JSON valide. Pas de markdown, pas d'explication, 
pas de texte supplémentaire avant ou après l'objet JSON.

Si un champ ne peut pas être déterminé, utilise null.
Assure-toi que toutes les chaînes sont correctement entre guillemets et échappées.
Les nombres ne doivent pas être entre guillemets.
```

<Callout type="tip" title="Laissez l'API imposer le schéma">
Quand vous appelez un modèle via une API, la formulation n'est pas votre seul outil. OpenAI, Anthropic et Google proposent tous des fonctionnalités de sorties structurées qui prennent un JSON Schema et contraignent la réponse à s'y conformer. Cela élimine la plupart des échecs d'analyse décrits dans ce chapitre, comme les blocs markdown parasites, les virgules finales et les champs manquants. Les anciens réglages de « mode JSON » garantissent seulement un JSON syntaxiquement valide, pas le respect de votre schéma, et chaque fournisseur prend en charge un sous-ensemble légèrement différent de JSON Schema. Les techniques qui suivent restent utiles, car un schéma contrôle la forme de la réponse, pas la justesse des valeurs qu'elle contient.
</Callout>

## Bases du prompting YAML

YAML est plus lisible que JSON et accepte les commentaires. C'est le standard des fichiers de configuration, surtout en DevOps (Docker, Kubernetes, GitHub Actions).

### Sortie YAML simple

YAML utilise l'indentation au lieu des accolades. Fournissez un modèle qui montre la structure attendue.

```
Génère un fichier de configuration au format YAML :

server:
  host: string
  port: number
  ssl: boolean
database:
  type: string
  connection_string: string

Exigences : serveur de production sur le port 443 avec SSL, base de données PostgreSQL
```

Sortie :
```yaml
server:
  host: "0.0.0.0"
  port: 443
  ssl: true
database:
  type: "postgresql"
  connection_string: "postgresql://user:pass@localhost:5432/prod"
```

### Structures YAML complexes

Pour les configurations complexes, soyez précis sur les exigences. Le modèle connaît les schémas courants d'outils comme GitHub Actions, Docker Compose et Kubernetes.

```
Génère un workflow GitHub Actions en YAML :

Exigences :
- Déclenchement sur push vers main et sur les pull requests
- Exécution sur Ubuntu latest
- Étapes : checkout, installation de la version LTS actuelle de Node.js, installation des dépendances, exécution des tests
- Mise en cache des dépendances npm
```

Les définitions de types donnent au modèle un contrat précis pour la structure de sortie. Elles sont plus explicites que des exemples et plus faciles à valider par programme.

### Définition par JSON Schema

<Callout type="info" title="Standard du secteur">
JSON Schema est une spécification formelle pour décrire la structure d'un document JSON. Elle est prise en charge par de nombreuses bibliothèques de validation et de nombreux outils d'API.
</Callout>

JSON Schema fournit des contraintes comme des valeurs min/max, des champs obligatoires et des expressions régulières :

```
Extrais les données selon ce JSON Schema :

{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "required": ["titre", "auteur", "annee"],
  "properties": {
    "titre": { "type": "string" },
    "auteur": { "type": "string" },
    "annee": { "type": "integer", "minimum": 1000, "maximum": 2100 },
    "genres": { 
      "type": "array", 
      "items": { "type": "string" }
    },
    "note": { 
      "type": "number", 
      "minimum": 0, 
      "maximum": 5 
    }
  }
}

Livre : "1984 de George Orwell (1949) - Un chef-d'œuvre dystopique. 
Genres : science-fiction, fiction politique. Noté 4.8/5"
```

## Gestion des tableaux

Les tableaux demandent une attention particulière. Précisez si vous avez besoin d'un nombre fixe d'éléments ou d'une liste de longueur variable, et comment traiter les cas vides.

### Tableaux de longueur fixe

Quand vous avez besoin d'exactement N éléments, dites-le explicitement. Les modèles le respectent généralement, mais comptez les éléments dans votre code si le nombre est important.

```
Extrais exactement 3 points clés en JSON :

{
  "points_cles": [
    "string (premier point)",
    "string (deuxième point)", 
    "string (troisième point)"
  ]
}

Article : [texte de l'article]
```

### Tableaux de longueur variable

Pour les tableaux de longueur variable, précisez quoi faire quand il n'y a aucun élément. Ajouter un champ de comptage aide à vérifier que l'extraction est complète.

```
Extrais toutes les personnes mentionnées en JSON :

{
  "personnes": [
    {
      "nom": "string",
      "role": "string ou null si non mentionné"
    }
  ],
  "compte": number
}

Si aucune personne n'est mentionnée, retourne un tableau vide.

Texte : [texte]
```

## Valeurs enum et contraintes

Les enums restreignent les valeurs à un ensemble prédéfini. C'est essentiel pour les tâches de classification et partout où vous avez besoin de sorties cohérentes et prévisibles.

### À faire et à éviter : valeurs enum

<Compare 
  before={{ label: "❌ À éviter : catégories ouvertes", content: "Classe ce texte dans une catégorie.\n\n{\n  \"categorie\": \"string\"\n}" }}
  after={{ label: "✓ À faire : restreindre aux valeurs valides", content: "Classe ce texte. La catégorie DOIT être exactement l'une des suivantes :\n- \"technique\"\n- \"business\"\n- \"creatif\"\n- \"personnel\"\n\n{\n  \"categorie\": \"l'une des valeurs ci-dessus\"\n}" }}
/>

### Enums de chaînes

Listez explicitement les valeurs autorisées. Une formulation du type « DOIT être l'une des valeurs » impose une correspondance stricte.

```
Classe ce texte. La catégorie DOIT être l'une de ces valeurs exactes :
- "technique"
- "business" 
- "creatif"
- "personnel"

Retourne du JSON :
{
  "texte": "texte original (tronqué à 50 caractères)",
  "categorie": "l'une des valeurs enum ci-dessus",
  "confiance": nombre entre 0 et 1
}

Texte : [texte à classer]
```

### Nombres validés

Les contraintes numériques empêchent les valeurs hors plage. Précisez le type (entier ou décimal) et la plage valide.

```
Note ces aspects. Chaque note DOIT être un entier de 1 à 5.

{
  "qualite": 1-5,
  "rapport_qualite_prix": 1-5,
  "service": 1-5,
  "global": 1-5
}

Avis : [texte de l'avis]
```

## Gestion des données manquantes

Les textes réels omettent souvent certaines informations. Définissez comment le modèle doit traiter les données manquantes pour éviter qu'il invente des valeurs.

### À faire et à éviter : informations manquantes

<Compare 
  before={{ label: "❌ À éviter : laisser l'IA deviner", content: "Extrais tous les détails de l'entreprise en JSON :\n{\n  \"chiffre_affaires\": number,\n  \"employes\": number\n}" }}
  after={{ label: "✓ À faire : autoriser explicitement null", content: "Extrais les détails de l'entreprise. Utilise null pour tout champ qui n'est PAS explicitement mentionné. N'INVENTE PAS et n'estime PAS de valeurs.\n\n{\n  \"chiffre_affaires\": \"number ou null\",\n  \"employes\": \"number ou null\"\n}" }}
/>

### Valeurs null

Autorisez explicitement null et demandez au modèle de ne pas inventer d'informations. C'est plus sûr que de le laisser deviner.

```
Extrais les informations. Utilise null pour tout champ qui ne peut pas 
être déterminé à partir du texte. N'INVENTE PAS d'informations.

{
  "entreprise": "string ou null",
  "chiffre_affaires": "number ou null",
  "employes": "number ou null",
  "fondee": "number (année) ou null",
  "siege": "string ou null"
}

Texte : "Apple, dont le siège est à Cupertino, a été fondée en 1976."
```

Sortie :
```json
{
  "entreprise": "Apple",
  "chiffre_affaires": null,
  "employes": null,
  "fondee": 1976,
  "siege": "Cupertino"
}
```

### Valeurs par défaut

Quand des valeurs par défaut ont du sens, indiquez-les dans le schéma. C'est fréquent pour l'extraction de paramètres de configuration.

```
Extrais les paramètres, avec ces valeurs par défaut s'ils ne sont pas précisés :

{
  "theme": "clair" (défaut) | "sombre",
  "langue": "fr" (défaut) | autre code ISO,
  "notifications": true (défaut) | false,
  "taillePolice": 14 (défaut) | number
}

Préférences de l'utilisateur : "Je veux le mode sombre et un texte plus grand (18px)"
```

## Réponses à plusieurs objets

Il faut souvent extraire plusieurs éléments d'une seule entrée. Définissez la structure du tableau et les éventuelles exigences de tri ou de regroupement.

### Tableau d'objets

Pour des listes d'éléments similaires, définissez le schéma de l'objet une seule fois et précisez qu'il s'agit d'un tableau.

```
Convertis cette liste en tableau JSON :

[
  {
    "tache": "string",
    "priorite": "haute" | "moyenne" | "basse",
    "echeance": "date ISO (chaîne) ou null"
  }
]

Liste de tâches :
- Finir le rapport (urgent, pour demain)
- Appeler le dentiste (priorité basse)
- Relire la PR #123 (moyenne, pour vendredi)
```

### Objets regroupés

Les tâches de regroupement demandent une logique de catégorisation. Le modèle répartira les éléments dans les catégories que vous définissez.

```
Classe ces éléments par catégorie en JSON :

{
  "fruits": ["tableau de chaînes"],
  "legumes": ["tableau de chaînes"],
  "autres": ["tableau de chaînes"]
}

Éléments : pomme, carotte, pain, banane, brocoli, lait, orange, épinards
```

## Validation et gestion des erreurs

Pour les systèmes en production, intégrez la validation dans vos prompts. Vous interceptez ainsi les erreurs avant qu'elles ne se propagent dans votre pipeline.

### Prompt d'auto-validation

Demandez au modèle de valider sa propre sortie selon des règles que vous précisez. Cela permet de repérer les erreurs de format et les valeurs invalides.

```
Extrais les données en JSON, puis valide ta sortie.

Schéma :
{
  "email": "format d'email valide",
  "telephone": "format E.164 (+33123456789)",
  "date": "format ISO 8601 (AAAA-MM-JJ)"
}

Après avoir généré le JSON, vérifie :
1. L'email contient @ et un domaine valide
2. Le téléphone commence par + et ne contient que des chiffres
3. La date est valide et analysable

Si la validation échoue, corrige les problèmes avant de répondre.

Texte : [coordonnées]
```

### Format de réponse en cas d'erreur

Définissez des formats distincts pour le succès et l'erreur. Le traitement par programme en devient beaucoup plus simple.

```
Tente d'extraire les données. Si l'extraction échoue, retourne le format d'erreur :

Format de succès :
{
  "succes": true,
  "donnees": { ... données extraites ... }
}

Format d'erreur :
{
  "succes": false,
  "erreur": "description de ce qui n'a pas fonctionné",
  "donnees_partielles": { ... données qui ont pu être extraites ... }
}
```

## Enregistrer ses prompts structurés

Une fois qu'un prompt JSON ou YAML fonctionne bien, conservez-le dans un endroit où vous pourrez le retrouver et le réutiliser. Certaines bibliothèques de prompts, dont prompts.chat, permettent d'enregistrer un prompt lui-même rédigé en JSON ou en YAML, de l'afficher avec coloration syntaxique et de remplir ses variables de modèle avant de le copier. Gardez à l'esprit que cela stocke le prompt ; cela ne vérifie pas la réponse du modèle par rapport à un schéma. Pour cela, utilisez la fonctionnalité de sorties structurées de votre API ou validez la réponse dans votre propre code.

## Pièges courants

<Callout type="warning" title="À déboguer en premier">
Ces trois problèmes sont à l'origine de la plupart des échecs d'analyse JSON. Vérifiez-les quand votre code n'arrive pas à analyser la sortie de l'IA. Les sorties structurées avec schéma imposé les évitent en grande partie : ils comptent donc surtout quand vous vous reposez uniquement sur le prompt.
</Callout>

### 1. Blocs de code markdown

**Problème :** le modèle enveloppe le JSON dans des blocs ```json

**Solution :** 
```
Retourne UNIQUEMENT l'objet JSON. Ne l'enveloppe pas dans des blocs de code markdown.
N'inclus pas de marqueurs ```json ou ```.
```

### 2. Virgules finales

**Problème :** JSON invalide à cause de virgules finales

**Solution :**
```
Assure-toi que la syntaxe JSON est valide. Pas de virgule après le dernier 
élément des tableaux ou des objets.
```

### 3. Chaînes non échappées

**Problème :** des guillemets ou des caractères spéciaux cassent le JSON

**Solution :**
```
Échappe correctement les caractères spéciaux dans les chaînes :
- \" pour les guillemets
- \\ pour les barres obliques inverses
- \n pour les retours à la ligne
```

## Résumé

<Callout type="tip" title="Techniques clés">
Définissez les schémas explicitement avec des interfaces TypeScript ou JSON Schema. Précisez les types et les contraintes, gérez les valeurs null et par défaut, demandez une auto-validation et choisissez le format adapté à votre cas d'usage. Quand vous passez par une API, laissez sa fonctionnalité de sorties structurées imposer le schéma, et continuez à valider les valeurs.
</Callout>
