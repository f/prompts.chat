## JSON Promptlama Temelleri

JSON (JavaScript Object Notation), kodla işlenecek yapay zeka çıktıları için en yaygın formattır. Katı sözdizimi ayrıştırmayı kolaylaştırır; ama bu, küçük bir hatanın bütün pipeline'ınızı bozabileceği anlamına da gelir.

### Yapılması ve Yapılmaması Gerekenler: JSON İsterken

<Compare 
  before={{ label: "❌ Yapma: Belirsiz istek", content: "Kullanıcı bilgilerini JSON olarak ver." }}
  after={{ label: "✓ Yap: Şemayı göster", content: "Kullanıcı bilgilerini bu şemaya uygun JSON olarak çıkar:\n\n{\n  \"isim\": \"string\",\n  \"yas\": number,\n  \"email\": \"string\"\n}\n\nYALNIZCA geçerli JSON döndür, markdown kullanma." }}
/>

### Basit JSON Çıktı

İşe, beklenen yapıyı gösteren bir şemayla başlayın. Model, değerleri girdi metnine bakarak doldurur.

```
Aşağıdaki bilgileri JSON olarak çıkar:

{
  "isim": "string",
  "yas": number,
  "email": "string"
}

Metin: "Ahmet Yılmaz ile iletişime geçin, 34 yaşında, ahmet@example.com"
```

Çıktı:
```json
{
  "isim": "Ahmet Yılmaz",
  "yas": 34,
  "email": "ahmet@example.com"
}
```

### İç İçe JSON Yapıları

Gerçek dünyadaki veriler çoğu zaman iç içe ilişkiler barındırır. Şemanızın her seviyesini, özellikle de nesne dizilerini açıkça tanımlayın.

```
Bu siparişi JSON'a ayrıştır:

{
  "siparis_id": "string",
  "musteri": {
    "isim": "string",
    "email": "string"
  },
  "urunler": [
    {
      "urun": "string",
      "miktar": number,
      "fiyat": number
    }
  ],
  "toplam": number
}

Sipariş: "Ayşe Kaya (ayse@email.com) için #12345 numaralı sipariş: 2x Widget (tanesi 10 TL), 
1x Gadget (25 TL). Toplam: 45 TL"
```

### Geçerli JSON Almak

<Callout type="warning" title="Sık Görülen Hata Noktası">
Modeller JSON'u sık sık markdown kod bloğuna sarar ya da başına sonuna açıklama ekler. Yalnızca ham JSON istediğinizi açıkça belirtin.
</Callout>

Açık talimatlar ekleyin:

```
KRİTİK: YALNIZCA geçerli JSON döndür. Markdown yok, açıklama yok, 
JSON nesnesinden önce veya sonra ek metin yok.

Bir alan belirlenemiyorsa null kullan.
Tüm string'lerin düzgünce tırnak içine alındığından ve escape edildiğinden emin ol.
Sayılar tırnak içine alınmamalı.
```

<Callout type="tip" title="Şemaya Uyulmasını API Sağlasın">
Bir modeli API üzerinden çağırıyorsanız elinizdeki tek araç kelimeler değildir. OpenAI, Anthropic ve Google, bir JSON Schema alıp yanıtı ona uymaya zorlayan yapılandırılmış çıktı özellikleri sunuyor. Bu özellikler, bu bölümde anlatılan ayrıştırma hatalarının çoğunu, örneğin araya karışan markdown blok işaretlerini, sonda kalan fazla virgülleri ve eksik alanları baştan ortadan kaldırır. Eski "JSON modu" ayarları ise yalnızca sözdizimi geçerli bir JSON'u garanti eder, sizin şemanızı değil; üstelik her sağlayıcı JSON Schema'nın biraz farklı bir alt kümesini destekler. Aşağıdaki teknikler yine de önemini korur, çünkü şema yanıtın biçimini belirler, içindeki değerlerin doğru olup olmadığını değil.
</Callout>

## YAML Promptlama Temelleri

YAML, insanlar için JSON'dan daha kolay okunur ve yorum satırlarını destekler. Özellikle DevOps dünyasında (Docker, Kubernetes, GitHub Actions) yapılandırma dosyalarının standart formatıdır.

### Basit YAML Çıktı

YAML süslü parantez yerine girinti kullanır. Beklenen yapıyı gösteren bir şablon verin.

```
YAML formatında bir yapılandırma dosyası oluştur:

server:
  host: string
  port: number
  ssl: boolean
database:
  type: string
  connection_string: string

Gereksinimler: 443 portunda SSL'li production sunucusu, PostgreSQL veritabanı
```

Çıktı:
```yaml
server:
  host: "0.0.0.0"
  port: 443
  ssl: true
database:
  type: "postgresql"
  connection_string: "postgresql://user:pass@localhost:5432/prod"
```

### Karmaşık YAML Yapıları

Karmaşık yapılandırmalarda gereksinimleri net olarak belirtin. Model, GitHub Actions, Docker Compose ve Kubernetes gibi araçların yaygın kalıplarını bilir.

```
YAML formatında bir GitHub Actions iş akışı oluştur:

Gereksinimler:
- main'e push ve pull request'lerde tetiklensin
- Ubuntu latest üzerinde çalışsın
- Adımlar: checkout, Node.js'in güncel LTS sürümünü kurma, bağımlılıkları yükleme, testleri çalıştırma
- npm bağımlılıkları önbelleğe alınsın
```

### JSON Schema Tanımı

<Callout type="info" title="Endüstri Standardı">
JSON Schema, JSON yapısını tarif etmek için kullanılan resmi bir standarttır. Pek çok doğrulama kütüphanesi ve API aracı bu standardı destekler.
</Callout>

JSON Schema ile en küçük/en büyük değerler, zorunlu alanlar ve regex kalıpları gibi kısıtlar tanımlayabilirsiniz:

```
Bu JSON Schema'ya göre veri çıkar:

{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "required": ["baslik", "yazar", "yil"],
  "properties": {
    "baslik": { "type": "string" },
    "yazar": { "type": "string" },
    "yil": { "type": "integer", "minimum": 1000, "maximum": 2100 },
    "turler": { 
      "type": "array", 
      "items": { "type": "string" }
    },
    "puan": { 
      "type": "number", 
      "minimum": 0, 
      "maximum": 5 
    }
  }
}

Kitap: "George Orwell'in 1984'ü (1949) - Distopik bir başyapıt. 
Türler: Bilim Kurgu, Politik Kurgu. 4.8/5 puan"
```

## Dizileri İşleme

Diziler özel dikkat ister. Sabit sayıda öğeye mi yoksa uzunluğu değişebilen bir listeye mi ihtiyacınız olduğunu ve liste boş kaldığında ne yapılacağını belirtin.

### Sabit Uzunluklu Diziler

Tam olarak N öğeye ihtiyacınız varsa bunu açıkça belirtin. Modeller genellikle buna uyar, ama sayı sizin için önemliyse öğeleri kodunuzda ayrıca sayın.

```
Tam olarak 3 ana noktayı JSON olarak çıkar:

{
  "ana_noktalar": [
    "string (birinci nokta)",
    "string (ikinci nokta)", 
    "string (üçüncü nokta)"
  ]
}

Makale: [makale metni]
```

### Değişken Uzunluklu Diziler

Değişken uzunluklu dizilerde, hiç öğe olmadığında ne yapılacağını belirtin. Bir sayı alanı eklemek, çıkarılan verinin eksiksiz olup olmadığını kontrol etmenize yardım eder.

```
Bahsedilen tüm kişileri JSON olarak çıkar:

{
  "kisiler": [
    {
      "isim": "string",
      "rol": "string veya bahsedilmemişse null"
    }
  ],
  "sayi": number
}

Hiçbir kişiden bahsedilmiyorsa boş dizi döndür.

Metin: [metin]
```

## Çok Nesneli Yanıtlar

Çoğu zaman tek bir girdiden birden fazla öğe çıkarmanız gerekir. Dizi yapısını ve varsa sıralama/gruplama gereksinimlerini tanımlayın.

### Nesne Dizisi

Birbirine benzeyen öğelerden oluşan listelerde nesne şemasını bir kez tanımlayın ve bunun bir dizi olduğunu belirtin.

```
Bu listeyi JSON dizisine ayrıştır:

[
  {
    "gorev": "string",
    "oncelik": "yuksek" | "orta" | "dusuk",
    "sonTarih": "ISO tarih string'i veya null"
  }
]

Yapılacaklar listesi:
- Raporu bitir (acil, yarın teslim)
- Dişçiyi ara (düşük öncelik)
- PR #123'ü incele (orta, cuma teslim)
```

### Gruplandırılmış Nesneler

Gruplama görevleri bir sınıflandırma mantığı gerektirir. Model, öğeleri sizin tanımladığınız kategorilere yerleştirir.

```
Bu öğeleri kategorilere ayırıp JSON olarak döndür:

{
  "meyveler": ["string dizisi"],
  "sebzeler": ["string dizisi"],
  "diger": ["string dizisi"]
}

Öğeler: elma, havuç, ekmek, muz, brokoli, süt, portakal, ıspanak
```

## Doğrulama ve Hata İşleme

Canlı sistemlerde doğrulamayı promptlarınızın içine yerleştirin. Böylece hatalar pipeline boyunca yayılmadan yakalanır.

### Öz Doğrulama Promptu

Modelden, çıktısını sizin belirlediğiniz kurallara göre kendisinin doğrulamasını isteyin. Bu sayede format hataları ve geçersiz değerler yakalanır.

```
Veriyi JSON olarak çıkar, sonra çıktını doğrula.

Şema:
{
  "email": "geçerli email formatı",
  "telefon": "E.164 formatı (+901234567890)",
  "tarih": "ISO 8601 formatı (YYYY-AA-GG)"
}

JSON'u oluşturduktan sonra kontrol et:
1. Email @ ve geçerli bir alan adı içeriyor
2. Telefon + ile başlıyor ve yalnızca rakam içeriyor
3. Tarih geçerli ve ayrıştırılabilir

Doğrulama başarısız olursa, yanıt vermeden önce düzelt.

Metin: [iletişim bilgileri]
```

### Hata Yanıt Formatı

Başarı ve hata durumları için ayrı formatlar tanımlayın. Bu, yanıtı kodla işlemeyi çok kolaylaştırır.

```
Veri çıkarmayı dene. Çıkarma başarısız olursa hata formatında yanıt döndür:

Başarı formatı:
{
  "basarili": true,
  "veri": { ... çıkarılan veri ... }
}

Hata formatı:
{
  "basarili": false,
  "hata": "neyin yanlış gittiğinin açıklaması",
  "kismi_veri": { ... çıkarılabilen veri ... }
}
```

## Yapılandırılmış Promptları Saklamak

Bir JSON ya da YAML promptu iyi çalışmaya başladığında, onu kolayca bulup yeniden kullanabileceğiniz bir yerde saklayın. Bazı prompt kütüphaneleri (prompts.chat de bunlardan biri), kendisi JSON ya da YAML ile yazılmış bir promptu kaydetmenize, sözdizimi vurgulamasıyla görüntülemenize ve kopyalamadan önce şablon değişkenlerini doldurmanıza imkân tanır. Yalnız şunu unutmayın: bu özellik promptu saklar, modelin yanıtını bir şemaya göre denetlemez. Bunun için API'nizin yapılandırılmış çıktı özelliğini kullanın ya da yanıtı kendi kodunuzda doğrulayın.

## Yaygın Tuzaklar

<Callout type="warning" title="Önce Bunlara Bakın">
JSON ayrıştırma hatalarının çoğu bu üç sorundan kaynaklanır. Kodunuz yapay zeka çıktısını ayrıştıramadığında önce bunları kontrol edin. Şemaya uyulmasını zorunlu kılan yapılandırılmış çıktı özellikleri bu sorunların büyük kısmını baştan önler; bu yüzden asıl önemli oldukları yer, yalnızca prompta güvendiğiniz durumlardır.
</Callout>

### 1. Markdown Kod Blokları

**Problem:** Model JSON'u ```json bloklarının içine sarıyor

**Çözüm:** 
```
YALNIZCA JSON nesnesini döndür. Markdown kod bloğu kullanma.
Başına ```json, sonuna ``` gibi işaretler ekleme.
```

### 2. Sondaki Fazla Virgüller

**Problem:** Sonda kalan fazladan virgüller JSON'u geçersiz kılıyor

**Çözüm:**
```
Sözdizimi geçerli bir JSON üret. Dizilerde veya nesnelerde son 
öğeden sonra virgül olmamalı.
```

### 3. Escape Edilmemiş String'ler

**Problem:** Tırnak işaretleri veya özel karakterler JSON'u bozuyor

**Çözüm:**
```
String'lerdeki özel karakterleri düzgünce escape et:
- tırnak işaretleri için \"
- ters eğik çizgiler için \\
- yeni satırlar için \n
```

Tipleri ve kısıtları belirtin, null ve varsayılan değerleri ele alın, modelden kendi çıktısını doğrulamasını isteyin ve ihtiyacınıza uygun formatı seçin. API üzerinden çalışıyorsanız şemaya uyulmasını API'nin yapılandırılmış çıktı özelliğine bırakın, değerleri doğrulamayı ise sürdürün.
