JSON (JavaScript Object Notation) süni intellektin proqram tərəfindən emal olunan çıxışları üçün ən geniş yayılmış formatdır. Onun ciddi sintaksisi təhlili asanlaşdırır, amma bu həm də o deməkdir ki, kiçik xətalar bütün pipeline-ınızı poza bilər.

### Edilməli və Edilməməli: JSON İstəmə

### Sadə JSON Çıxış

Gözlənilən strukturu göstərən sxemlə başlayın. Model dəyərləri giriş mətninə əsasən dolduracaq.

```
Aşağıdakı məlumatları JSON olaraq çıxar:

{
  "name": "string",
  "age": number,
  "email": "string"
}

Mətn: "Əhməd Məmmədovla əlaqə saxlayın, 34 yaşındadır, ahmed@example.com"
```

Çıxış:
```json
{
  "name": "Əhməd Məmmədov",
  "age": 34,
  "email": "ahmed@example.com"
}
```

### İç-içə JSON Strukturları

Real məlumatlarda çox vaxt iç-içə əlaqələr olur. Sxeminizin hər səviyyəsini, xüsusilə obyekt massivlərini aydın şəkildə təyin edin.

```
Bu sifarişi JSON-a çevir:

{
  "order_id": "string",
  "customer": {
    "name": "string",
    "email": "string"
  },
  "items": [
    {
      "product": "string",
      "quantity": number,
      "price": number
    }
  ],
  "total": number
}

Sifariş: "Aynur Əliyeva (aynur@email.com) üçün #12345 nömrəli sifariş: 2x Widget (ədədi 10 AZN), 
1x Gadget (25 AZN). Cəmi: 45 AZN"
```

### Etibarlı JSON-u Təmin Etmə

<Callout type="warning" title="Tez-tez Rast Gəlinən Xəta">
Modellər çox vaxt JSON-u markdown kod bloklarına salır və ya izahedici mətn əlavə edir. Yalnız xam JSON istədiyinizi açıq şəkildə bildirin.
</Callout>

Açıq təlimatlar əlavə edin:

```
KRİTİK: YALNIZ etibarlı JSON qaytar. Markdown yox, izahat yox, 
JSON obyektindən əvvəl və ya sonra əlavə mətn yox.

Bir sahəni müəyyən etmək mümkün deyilsə, null istifadə et.
Bütün string-lərin düzgün dırnaqlanıb escape edildiyindən əmin ol.
Rəqəmlər dırnaq içində olmamalıdır.
```

<Callout type="tip" title="Sxemə Riayəti API-yə Həvalə Edin">
Modeli API vasitəsilə çağırdığınız zaman yeganə alətiniz ifadələr deyil. OpenAI, Anthropic və Google JSON Schema qəbul edən və cavabı ona uyğun olmağa məcbur edən strukturlaşdırılmış çıxış funksiyaları təklif edir. Bu, bu fəsildə bəhs olunan təhlil xətalarının çoxunu, məsələn, artıq markdown işarələrini, sondakı artıq vergülləri və çatışmayan sahələri aradan qaldırır. Köhnə "JSON rejimi" parametrləri yalnız sintaktik cəhətdən etibarlı JSON-a zəmanət verir, sizin sxeminizə yox; üstəlik, hər provayder JSON Schema-nın bir qədər fərqli alt çoxluğunu dəstəkləyir. Aşağıdakı texnikalar yenə də vacibdir, çünki sxem cavabın formasını idarə edir, içindəki dəyərlərin düzgün olub-olmamasını yox.
</Callout>

## YAML Prompting Əsasları

YAML insan üçün JSON-dan daha oxunaqlıdır və şərhləri dəstəkləyir. O, konfiqurasiya faylları üçün, xüsusilə DevOps-da (Docker, Kubernetes, GitHub Actions) standartdır.

### Sadə YAML Çıxış

YAML mötərizələr əvəzinə sətir başındakı boşluqlardan (abzaslardan) istifadə edir. Gözlənilən strukturu göstərən şablon verin.

```
YAML formatında konfiqurasiya faylı yarat:

server:
  host: string
  port: number
  ssl: boolean
database:
  type: string
  connection_string: string

Tələblər: 443-cü portda SSL ilə işləyən istehsal serveri, PostgreSQL verilənlər bazası
```

Çıxış:
```yaml
server:
  host: "0.0.0.0"
  port: 443
  ssl: true
database:
  type: "postgresql"
  connection_string: "postgresql://user:pass@localhost:5432/prod"
```

### Mürəkkəb YAML Strukturları

Mürəkkəb konfiqurasiyalar üçün tələbləri konkret göstərin. Model GitHub Actions, Docker Compose və Kubernetes kimi alətlər üçün geniş yayılmış qəlibləri bilir.

```
YAML-da GitHub Actions iş axını yarat:

Tələblər:
- main-ə push və pull request-lərdə işə düşsün
- Ubuntu latest üzərində işləsin
- Addımlar: checkout, Node.js-in cari LTS buraxılışının quraşdırılması, asılılıqların yüklənməsi, testlərin işə salınması
- npm asılılıqlarını keşlə
```

## Massivlərlə İşləmə

Massivlər xüsusi diqqət tələb edir. Sabit sayda elementə, yoxsa dəyişən uzunluqlu siyahıya ehtiyacınız olduğunu və element olmadıqda nə edilməli olduğunu göstərin.

### Sabit Uzunluqlu Massivlər

Sizə tam olaraq N element lazımdırsa, bunu açıq şəkildə bildirin. Modellər adətən buna əməl edir, amma say vacibdirsə, elementləri öz kodunuzda yoxlayın.

```
Tam olaraq 3 əsas fikri JSON olaraq çıxar:

{
  "key_points": [
    "string (birinci fikir)",
    "string (ikinci fikir)", 
    "string (üçüncü fikir)"
  ]
}

Məqalə: [məqalə mətni]
```

### Dəyişən Uzunluqlu Massivlər

Dəyişən uzunluqlu massivlər üçün heç bir element olmadıqda nə ediləcəyini göstərin. Say sahəsi əlavə etmək çıxarışın tamlığını yoxlamağa kömək edir.

```
Mətndə adı çəkilən bütün şəxsləri JSON olaraq çıxar:

{
  "people": [
    {
      "name": "string",
      "role": "string və ya qeyd olunmayıbsa null"
    }
  ],
  "count": number
}

Heç bir şəxsin adı çəkilməyibsə, boş massiv qaytar.

Mətn: [mətn]
```

## Çox Obyektli Cavablar

Çox vaxt bir girişdən bir neçə element çıxarmaq lazım gəlir. Massivin strukturunu və sıralama/qruplaşdırma tələblərini müəyyən edin.

### Obyekt Massivi

Oxşar elementlərin siyahıları üçün obyekt sxemini bir dəfə təyin edin və bunun massiv olduğunu göstərin.

```
Bu siyahını JSON massivinə çevir:

[
  {
    "task": "string",
    "priority": "high" | "medium" | "low",
    "due": "ISO tarix string-i və ya null"
  }
]

Görüləcək işlər:
- Hesabatı bitir (təcili, sabaha qədər)
- Diş həkiminə zəng et (aşağı prioritet)
- PR #123-ə bax (orta, cüməyə qədər)
```

### Qruplaşdırılmış Obyektlər

Qruplaşdırma tapşırıqları kateqoriyalaşdırma məntiqi tələb edir. Model elementləri sizin müəyyən etdiyiniz kateqoriyalara ayıracaq.

```
Bu elementləri kateqoriyalara ayırıb JSON-a çevir:

{
  "fruits": ["string massivi"],
  "vegetables": ["string massivi"],
  "other": ["string massivi"]
}

Elementlər: alma, kök, çörək, banan, brokoli, süd, portağal, ispanaq
```

## Doğrulama və Xətaların İdarə Edilməsi

İstehsal sistemlərində doğrulamanı promptlarınızın içinə qurun. Bu, xətaları pipeline boyunca yayılmazdan əvvəl tutmağa imkan verir.

### Öz-Doğrulama Promptu

Modeldən çıxışını sizin göstərdiyiniz qaydalara əsasən yoxlamasını istəyin. Bu, format xətalarını və etibarsız dəyərləri tutur.

```
Məlumatı JSON olaraq çıxar, sonra çıxışını yoxla.

Sxem:
{
  "email": "etibarlı email formatı",
  "phone": "E.164 formatı (+994123456789)",
  "date": "ISO 8601 formatı (YYYY-MM-DD)"
}

JSON yaratdıqdan sonra yoxla:
1. Email-də @ və etibarlı domen var
2. Telefon + ilə başlayır və yalnız rəqəmlərdən ibarətdir
3. Tarix etibarlıdır və təhlil edilə bilir

Yoxlama uğursuz olarsa, cavab verməzdən əvvəl problemləri düzəlt.

Mətn: [əlaqə məlumatları]
```

### Xəta Cavabının Formatı

Uğurlu nəticə və xəta üçün ayrı formatlar təyin edin. Bu, proqram tərəfindən emalı xeyli asanlaşdırır.

```
Məlumatı çıxarmağa çalış. Çıxarış alınmasa, xəta formatını qaytar:

Uğur formatı:
{
  "success": true,
  "data": { ... çıxarılmış məlumat ... }
}

Xəta formatı:
{
  "success": false,
  "error": "nəyin səhv getdiyinin izahı",
  "partial_data": { ... çıxarıla bilən məlumat ... }
}
```

## Strukturlaşdırılmış Promptların Saxlanması

JSON və ya YAML promptu yaxşı işləyəndə, onu tapıb yenidən istifadə edə biləcəyiniz yerdə saxlayın. Bəzi prompt kitabxanaları, o cümlədən prompts.chat, özü JSON və ya YAML ilə yazılmış promptu saxlamağa, onu sintaksis vurğulaması ilə göstərməyə və kopyalamazdan əvvəl şablon dəyişənlərini doldurmağa imkan verir. Yadda saxlayın ki, bu, yalnız promptu saxlayır; modelin cavabını sxemə uyğunluq baxımından yoxlamır. Bunun üçün API-nizin strukturlaşdırılmış çıxış funksiyasından istifadə edin və ya cavabı öz kodunuzda yoxlayın.

## Tez-tez Rast Gəlinən Tələlər

<Callout type="warning" title="Əvvəlcə Bunları Yoxlayın">
JSON təhlili xətalarının çoxuna bu üç problem səbəb olur. Kodunuz süni intellekt çıxışını təhlil edə bilmədikdə əvvəlcə bunları yoxlayın. Sxemə riayəti məcburi edən strukturlaşdırılmış çıxış bu problemlərin qarşısını əsasən alır, ona görə də onlar ən çox yalnız promptun özünə güvəndiyiniz hallarda önəmlidir.
</Callout>

### 1. Markdown Kod Blokları

**Problem:** Model JSON-u ```json bloklarına salır

**Həll:** 
```
YALNIZ JSON obyektini qaytar. Onu markdown kod bloklarına salma.
Cavaba ```json və ya ``` işarələrini əlavə etmə.
```

### 2. Sondakı Artıq Vergüllər

**Problem:** Sondakı artıq vergüllər səbəbindən etibarsız JSON

**Həll:**
```
JSON sintaksisinin etibarlı olduğundan əmin ol. Massivlərdə və ya obyektlərdə son 
elementdən sonra vergül olmamalıdır.
```

### 3. Escape Edilməmiş String-lər

**Problem:** Dırnaq işarələri və ya xüsusi simvollar JSON-u pozur

**Həll:**
```
String-lərdəki xüsusi simvolları düzgün escape et:
- \" dırnaq işarələri üçün
- \\ tərs slash-lar üçün
- \n yeni sətirlər üçün
```
