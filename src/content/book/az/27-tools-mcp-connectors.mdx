Agentdən layihənizdəki açıq xətaları tapmasını və əlavə iş üçün qeyd qaralaması hazırlamasını istəyirsiniz. Bunun üçün yaxşı təlimatlardan daha çox şey lazımdır. Agent xəta izləmə sisteminizə çatmalı, düzgün məlumatı oxumalı və bəlkə də orada yeni qeyd yaratmalıdır.

## Alət Əslində Nələrdən İbarətdir?

Alətin adətən **adı**, **təsviri**, **giriş sxemi** və işi görən proqram kodu olur. Təsvir modelə aləti nə vaxt istifadə edəcəyini seçməyə kömək edir. Sxem qəbul edilən arqumentləri təsvir edir.

Budur kiçik, uydurma MCP alətinin tərifi:

<Collapsible title="search_issues tərifini nəzərdən keçirin">

```json
{
  "name": "search_issues",
  "description": "Bağlı layihədə qeydləri axtar. Bu alət yalnız məlumat oxuyur.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": { "type": "string" },
      "limit": { "type": "integer", "minimum": 1, "maximum": 20 }
    },
    "required": ["query"],
    "additionalProperties": false
  }
}
```

</Collapsible>

Model `{"query": "açıq xətalar", "limit": 3}` arqumentləri ilə `search_issues` sorğusu verə bilər. Tətbiq bu sorğunu əməliyyatı icra edən koda yönəldir. Kod izləmə sisteminə sorğu göndərir və nəticələri və ya xətanı qaytarır.

Ad və sxem öz-özünə heç nə icra etmir. Alətin kodu girişləri yoxlamalı, girişi nəzarətdə saxlamalı və həqiqi əməliyyatı yerinə yetirməlidir. Alətin cavabı da modelin yekun cavabından ayrıdır: cavabda qeyd identifikatorları və başlıqlar ola bilər, model isə onları xülasə edir. [MCP alətləri spesifikasiyası](https://modelcontextprotocol.io/specification/latest/server/tools) alətlərin bu əməliyyatları necə təqdim etdiyini izah edir.

<Callout type="info" title="Sorğu nəticə deyil">
"Qeyd yaradacağam" bir ifadədir. Alət çağırışı əməliyyatı tələb edir. Yeni qeydin identifikatorunu ehtiva edən uğurlu cavab isə əməliyyatın baş verdiyinə sübutdur. Bu üç şeyi ayırın.
</Callout>

## Bağlayıcı Nə Əlavə Edir?

Bağlayıcı müəyyən sistemlə inteqrasiyanı birləşdirir. Daxil olmağı, hesab və ya iş sahəsi seçməyi, məlumat tapmağı və dəstəklənən əməliyyatları alət kimi təqdim etməyi idarə edə bilər. Bəzi bağlayıcılar yalnız axtarır və ya oxuyur. Digərləri yazmanı da dəstəkləyir.

**Bağlayıcı vahid universal texniki standart deyil, məhsul terminidir.** Bir bağlayıcı xidmətin API-sini birbaşa çağıra bilər. Digəri MCP serverindən istifadə edə bilər. Başqası sinxronlaşdırılmış sənədlərdən yaradılan indeksdə axtara bilər. Konkret inteqrasiyanın nəyi dəstəklədiyini yoxlayın. Microsoft-un [bağlayıcılara ümumi baxışı](https://learn.microsoft.com/en-us/azure/connectors/introduction) API-lər üzərində qurulan inteqrasiyalara bir nümunə verir.

Hesabı bağlamaq agentin hər faylı gördüyü, bütün məlumatınızı kontekstinə yüklədiyi və ya hər əməliyyata icazəsi olduğu demək deyil. Giriş hesabdan, təyin edilmiş icazə əhatələrindən, tətbiqdən və xidmətin öz icazələrindən asılıdır. Axtarış nəticələri də orijinal sənədlərdən daha köhnə indeksə əsaslana bilər.

Xəta izləmə sistemi üçün bu sualları ayrı saxlayın: Bağlantı qurulubmu? Hansı layihəyə girişi var? Yalnız oxuya bilər, yoxsa qeyd də yarada bilər?

## MCP Nəyi Standartlaşdırır?

**MCP**, **Model Context Protocol** ifadəsinin qısaltmasıdır. Süni intellekt tətbiqləri və xarici imkan təminatçıları arasında əlaqə üçün ortaq yol müəyyən edir. Xidmətin API-sini əvəz etmir; MCP serveri arxa planda həmin API-dən istifadə edə bilər.

Alət çağırışı üçün müştəri `tools/list` ilə serverin alətlərini tapa bilər. Tətbiq uyğun alət təriflərini modelə təqdim edir. Model onlardan birini istəyirsə, tətbiq MCP müştərisi vasitəsilə `tools/call` sorğusu göndərə bilər. Server əməliyyatı icra edir və ya başqa hissəyə ötürür, sonra nəticəni qaytarır.

Modelin özünün şəbəkə bağlantısı açması lazım deyil. Əlaqəni tətbiq və MCP-ni həyata keçirən proqram idarə edir. Uyğunluq yenə vacibdir: əsas tətbiq və server istifadə etmək istədiyiniz imkanları dəstəkləməlidir. Aləti tapmaq onu işlətməyə icazə vermir; giriş yoxlamaları yenə tətbiq olunur.

### Bacarıqlar da Serverlə Birlikdə Gələ Bilər

Bu yaxınlara qədər bu iki hissə adətən ayrı-ayrılıqda gəlirdi. Server agentə alətlərini verə bilirdi, lakin onlardan yaxşı istifadə etməyin incəlikləri başqa yerdə qalırdı: ayrıca quraşdırılan bir bacarıqda, README faylında və ya istifadəçinin öz promptunda. Xidmət dəyişəndə bu təlimatlar heç kimin xəbəri olmadan geridə qala bilirdi.

MCP-nin 2026-cı ilin sentyabrında yekunlaşan rəsmi **Skills genişlənməsi** bu boşluğun böyük hissəsini aradan qaldırır. İndi server təkcə alətlərini deyil, onlardan necə istifadə ediləcəyini izah edən bacarıqları da təqdim edə bilər. Bu bacarıqlar [Agentlər və Bacarıqlar](/book/25-agents-and-skills) fəslində təsvir olunan eyni `SKILL.md` formatında yazılır. Alətlər agentə nə edə biləcəyini deyir, bacarıqlar isə işi necə yaxşı görəcəyini. İndi hər ikisi eyni serverdən gələ bilər; beləcə təlimatlar təsvir etdikləri xidmətin yanında yaşayır və həmin xidməti dəstəkləyən insanlar onları aktual saxlaya bilir.

Mexanizm artıq tanış olduğunuz hissələrə əsaslanır. Bacarıqdakı hər fayl MCP resursu kimi təqdim olunur və adətən `skill://` ilə başlayan URI daşıyır. Müştəri serverin bacarıqlarını `skills/list` ilə siyahıya ala, birini `skills/get` ilə əldə edə və köməkçi fayllarını `resources/read` ilə oxuya bilər.

Bacarığın modelə necə çatacağına yenə də əsas tətbiq qərar verir. Model onu adına və təsvirinə görə seçə bilər, ya da istifadəçi birbaşa seçə bilər. Hər iki halda tam təlimatlar yalnız lazım olduqda kontekstə daxil olur və `SKILL.md` faylını oxumaq bacarığı öz-özlüyündə aktivləşdirmir.

<Callout type="warning" title="Serverdən gələn bacarıq da təlimatdır">
Serverdən gələn bacarıq agentin kontekstinə daxil olan mətndir və agentin sonrakı addımlarını formalaşdıra bilər. Ona görə də serverin özü qədər diqqətlə yoxlanmalıdır. Diqqətli əsas tətbiq məzmunu yükləməzdən əvvəl yoxlayır və lazım olan təsdiqi istəyir. MCP Apps və MCP Tasks kimi digər rəsmi MCP genişlənmələri kimi, Skills də məcburi deyil: yalnız həm müştəri, həm də server onu dəstəklədiyini bildirdikdə istifadə olunur. Müştəri dəstəyi hələ ilkin mərhələdədir, buna görə də ona güvənməzdən əvvəl tətbiqinizin serverlərdən bacarıqları həqiqətən yüklədiyini yoxlayın.
</Callout>

Agentə hansı məlumatı axtarmalı, ondan necə istifadə etməli olduğunu və hansı əməliyyatları gözlədiyinizi deyin. Bağlantının mövcud olduğunu və ya alətin xidmətdəki hər əməliyyatı dəstəklədiyini fərz etməyin.

Təkrar istifadə olunan qeyd qiymətləndirmə bacarığı üsulu əlavə edə bilər: təkrar qeydləri yoxla, problemi təkrar yaratma addımlarını müqayisə et, layihənin qeyd şablonunu izlə və cavabsız sualları bildir. Alət əməliyyatı təmin edir. Bacarıq ondan düzgün istifadə etməyi izah edir.

Alət çıxışını da qiymətləndirmək lazımdır. Qeyd şərhi, sənəd və ya axtarış nəticəsində səhvlər və ya təlimata bənzər mətn ola bilər. Gətirilən məzmunun istifadəçinin istəyini və ya tətbiqin qaydalarını dəyişməsinə imkan verməyin; onu məlumat kimi qəbul edin. Təkcə MCP dəstəyi serveri və məzmununu etibarlı etmir.

Oxuma uğursuz olarsa, agent xətanı bildirə və ya uyğun alternativ sınaya bilər. Yazma sorğusunun vaxtı bitərsə, təkrarlamazdan əvvəl dəyişikliyin baş verib-vermədiyini yoxlamalıdır. Əks halda təkrar cəhd eyni qeydi iki dəfə yarada bilər. Giriş məlumatları tapşırıq prompt-una deyil, inteqrasiyanın bağlantı ayarlarına aiddir. [Daim İşləyən Botlar](/book/28-persistent-bots) bölməsində təsvir edildiyi kimi, bot siz uzaqda olarkən alətlərdən cədvəl üzrə istifadə edəndə bu qaydalar daha da vacib olur.
